# 诸世问道：Anchor / 回溯 / 承世 / 悟世二次审视

> 状态：Matt `grill-with-docs` 第 11 轮后修正。
>
> 核心修正：Anchor 不再解释成复杂的“命轮之外历史实体”，而是一个受游戏规则限制的特殊检查点存档。

## 1. Anchor 的本质

Anchor 本质上就是：

> **一个只能在特定规则下建立、死亡后才能用于回溯的完整检查点存档。**

它与普通 SaveGame 的区别主要来自玩法限制，而不是来自另一套复杂世界观模型：

- 普通 SaveGame 用于保存退出和继续游戏。
- Anchor 用于死亡后的跨世回溯。
- Anchor 是完整世界快照。
- Anchor 建立后不可覆盖或修改。
- 每个大境界最多建立一个 Anchor。
- 初始 Anchor 自动创建。

玩家界面仍可以使用“天衍锚点 / 定世点”等修仙包装，但领域模型与实现均按特殊 checkpoint 理解。

## 2. 回溯 = 读取 Anchor + 叠加跨世状态

角色死亡并选择 Anchor 后，标准过程应理解为：

```text
读取 Anchor 完整快照
↓
恢复该时刻玩家 / NPC / 世界状态
↓
叠加不属于快照的跨世状态
├─ Knowledge
├─ Trait Library / 本世选择 Trait
├─ 剩余回溯次数
└─ 本次承世结果
↓
开始下一世
```

因此无需再引入“多个真实历史同时存在”“命轮外坐标”等复杂解释。

## 3. 每世界基础 10 次回溯

- 每个新 World 基础拥有 10 次回溯。
- 第一世不消耗回溯次数。
- 每次死亡后成功开启下一世，消耗 1 次。
- 普通游戏流程不能稳定刷取或恢复回溯次数。
- 回溯为 0 时当前一世仍能继续；再次死亡则该 World 结束。

回溯次数是有限的 Roguelite 资源。

## 4. 多个 Anchor 就是多个受保护检查点

一个 World 可以同时保存多个 Anchor，例如：

```text
炼气 Anchor
筑基 Anchor
紫府 Anchor
```

从炼气 Anchor 重新开始后，筑基 / 紫府 Anchor 不需要被删除，因为它们只是已经建立并保留的其他 checkpoint 快照。

这不代表游戏需要模拟多条并行世界线；系统只运行当前被读取的那一条人生。

后续死亡时仍可重新选择任意已保存 Anchor，等价于从另一个受保护 checkpoint 开始下一世。

## 5. 每个大境界只能建立一个 Anchor

这一限制继续保留，因为它承担的是玩法约束：

- 防止 Anchor 退化成无限手动存档。
- 让“什么时候定世”成为战略决定。
- 控制可回溯节点数量。

规则：

- 初始 Anchor 自动占用初始大境界 Anchor 位。
- 后续每个大境界最多一个 Anchor 位。
- 玩家在该境界尚未使用 Anchor 位时可以手动定世。
- 一旦建立，不可覆盖、不可更新。

## 6. Anchor 保存完整世界快照

Anchor 保存建立时完整的现实状态，包括：

- 当前世界时间。
- 玩家角色状态。
- 境界、修为、功法与术法掌握。
- 装备、法宝、物品。
- NPC 状态、生死、位置与关系。
- 玩家身份。
- 势力状态。
- 资源归属。
- Event Chain 状态。
- 地图 / 地点变化。
- 市场 / 地区状态。

不属于 Anchor 快照、而在读取后额外叠加的跨世状态：

- Knowledge。
- Trait Library。
- 剩余回溯次数。
- 本次死亡结算产生的承世结果。

## 7. 死亡结算顺序

继续保持：

```text
死亡
→ 冻结本世状态
→ 一世总结
→ 更新 Knowledge / 历史
→ 选择下一世 Anchor
→ 承世 OR 悟世
→ 配置下一世 Trait
→ 消耗一次回溯
→ 读取 Anchor 并叠加跨世状态
→ 开启下一世
```

先选 Anchor，再决定承世 / 悟世，因为同一成果带回不同 checkpoint 的价值可能完全不同。

## 8. 承世：一次带一项合法成果

承世可以携带一项本世死亡时仍合法拥有或掌握的成果。

### 可承世实体成果

- 法宝。
- 装备。
- 丹药。
- 特殊材料。
- 普通合法物品。

### 可承世修炼成果

- 一门功法的实际掌握状态。
- 一门术法的实际掌握状态。
- 其他明确允许的单项修炼成果。

### 绝对不可承世

- 境界。
- 修为。
- 境界派生基础能力。
- 筑基道基、紫府、金丹等大境界本体结构。

高阶成果带回低境界 Anchor 后仍受当前身体、境界、法力和使用条件限制。

## 9. Knowledge 与承世的边界

Knowledge 保留的是：

> 我知道怎样练、哪里容易错、谁能教、什么条件更合适。

承世保留的是：

> 这一项合法成果本身被直接带进下一世。

所以 Knowledge 可以大幅降低重新学习成本，但不会自动继承前世的全部身体适应、修为和能力。

## 10. 唯一物按“当前活动人生不重复”处理

不再需要把唯一物解释成跨所有 Anchor 的神秘世界级实体。

每个唯一物拥有稳定 `UniqueId`。当读取 Anchor 并叠加承世结果时，系统执行去重与来源校验：

- 当前活动人生中，同一个 `UniqueId` 最多存在一份。
- 如果承世把唯一物带到其原本获取时间之前，则当前人生后续原获取点不能再次生成第二份。
- 如果所选 Anchor 本身已经包含同一个 `UniqueId`，则不再额外叠加第二份。
- 其他尚未读取的 Anchor 只是独立 checkpoint 快照，不需要被跨存档追溯修改。

这样即可解决复制漏洞，不必维护复杂的“所有历史共享唯一物状态”。

## 11. 悟世与 Trait

悟世继续采用：

- 根据本世真实经历生成最多 3 个代表性 Trait 候选。
- 玩家选择 1 个加入当前 World 的 Trait Library。
- 无有效经历时允许没有候选。
- 同源 Trait 可以继续成长。
- 每一世最多装备 5 个 Trait。

Trait 定位为人生留下的规则印记，优先提供信息能力、特殊判断、事件选项、条件性规则变化与特殊生存 / 战斗机制，而不是永久百分比数值堆叠。

## 12. Trait 与境界门槛

Trait 跨 Anchor 保留，但可以根据当前境界分阶段生效。

例如：

```text
炼气 → 微弱感应
筑基 → 主要效果
紫府 → 完整效果
```

这样低境界角色不会因为高境界前世经历而直接越过当前能力边界。

## 13. 新 World 的 Meta Progression

一个 World 真正结束后：

- Knowledge 清空。
- Trait Library 清空。
- Anchor 清空。
- 当前世界物品与修为清空。

不采用永久战力堆叠。

允许保留内容型 Meta Progression，例如世界史 / 命书收藏、已见内容图鉴、Steam 成就、挑战条件、新世界模板、新出身与新内容模块。

## 14. 设计原则

Anchor 以后统一按下面一句话理解：

> **Anchor 就是多世玩法专用的特殊 checkpoint；复杂的是“死亡后允许带什么回来”，不是存档本身。**

这能显著降低规则解释、存档架构、唯一物处理和玩家理解成本。
