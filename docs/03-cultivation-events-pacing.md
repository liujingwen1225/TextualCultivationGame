# 诸世问道：修炼、事件与节奏系统

> 状态：Steam 像素 RPG 重设计当前有效基线

## 1. 设计目标

修仙成长必须有分量，但不能依靠现实挂机时间、超长经验条或无意义跑图制造时长。

核心原则：

> **有意义的行动推进游戏内时间，时间推动世界变化，世界变化反过来制造新的修炼与人生选择。**

## 2. 游戏内时间模型

桌面像素 RPG 引入真实地图移动后，需要区分“玩家操作时间”和“世界规则时间”。

### 2.1 不采用现实秒 = 游戏秒

玩家站在原地、打开背包、调整设置或绕着房间走，不应该让世界按现实秒数持续推进数日。

否则会出现：

- UI 操作影响世界命运。
- 帧率影响事件。
- 玩家故意挂机刷时间。
- 多世复现失去稳定性。

### 2.2 时间由有意义行为推进

典型时间消耗：

```text
同一建筑内移动 / 对话浏览
→ 通常不单独推进宏观时间

本地调查 / 采集 / 普通交互
→ 按行为结算少量时间

跨区域旅行
→ 小时 / 天

修炼 / 炼丹 / 养伤
→ 天 / 月

闭关
→ 月 / 年
```

具体数值由平衡阶段确定。

### 2.3 地图移动不是事件压力货币

移动步数、键盘输入次数、渲染帧数不能直接增加 Event Pressure。

玩家在青玄宗里多绕三圈，不应该因此更容易触发重大事件。

## 3. 微观时间与宏观时间

为了兼顾地图沉浸和修仙长时间尺度，推荐两层表达：

### 微观时间

用于：

- 当前时辰。
- NPC 是否在某地点。
- 商店是否开放。
- 夜间入口。
- 短途行动。

### 宏观时间

用于：

- 修炼。
- 闭关。
- 宗门阶段变化。
- NPC 长期事件。
- 秘境开启窗口。
- 年龄与寿元。

玩家执行长时间行为时，可以直接跳过宏观时间，但期间仍要进行事件调度。

## 4. 长时间行为

所有长期行为消耗世界时间：

- 修炼。
- 闭关。
- 长途旅行。
- 宗门任务。
- 炼丹 / 炼器。
- 秘境持续探索。
- 养伤。

例如：

```text
闭关 30 天
→ 世界时间 +30 天
→ 获得修为
→ 期间运行事件调度
→ 可能被宗门召集 / 遇到瓶颈 / 触发功法疑难
```

长时间行动不能成为无风险的“跳过世界按钮”。

## 5. 修为与境界

修为达到阈值只代表获得突破资格，不等于自动升级。

突破可以依赖：

- 功法理解。
- 身体状态。
- 灵根 / 资质。
- 丹药与材料。
- 心境 / 特殊经历。
- 地点 / 环境。

重大突破通过明确事件或高层流程结算，可以产生：

- 成功。
- 普通失败。
- 受伤。
- 根基受损。
- 走火入魔。
- 特殊感悟。
- 隐藏成长路线。

不要把重大突破退化成无上下文“63% 成功率按钮”。

## 6. 节奏指标

不规定：

- 首次筑基必须多少现实小时。
- 每个小境界必须多少分钟。
- 一世必须持续多少现实时间。

重点观察：

- 有效行动数量。
- 关键事件密度。
- 资源问题数量。
- 突破瓶颈数量。
- 重大选择频率。
- 可验证 Knowledge 数量。
- 重复人生机械操作量。

基础目标：

- 通常 2～4 个重大行动后，应出现一次有意义变化。
- 原则上不要连续超过 5 个重大行动完全没有新信息或新决策。
- 熟悉内容应逐步允许快捷处理。

## 7. Event Pressure

Event Pressure 用于判断“当前人生是否应该产生新的世界变化”。

主要输入：

- 经过的游戏内时间。
- 当前地图 / Zone 的事件密度。
- 当前剧情压力。
- 行动风险。
- 当前世界状态。
- 距离上一次重大事件的时间。
- 当前 Life Theme。

禁止把以下内容作为主要输入：

- 点击次数。
- 移动步数。
- 进入菜单次数。
- 请求次数。
- 渲染帧数。

同样 30 天的时间跨度，无论玩家拆成多个小修炼还是一次闭关，基础时间压力应该大体同级，再由行为性质产生差异。

## 8. 事件调度

事件来源：

- 核心事件链。
- NPC 人物事件。
- 宗门事件。
- 地点 / Zone 事件。
- 交互点事件。
- 奇遇。
- 秘境事件。
- 战斗结果。
- 修炼事件。
- 世界危机。

建议优先级：

```text
必须处理的强制事件
↓
关键事件链
↓
高相关 NPC / 地点事件
↓
普通随机事件
↓
低优先级氛围事件
```

需要：

- 冷却。
- 重复衰减。
- 核心剧情保护。
- 长时间无变化保护。

这些机制不直接暴露为玩家可刷的抽卡概率。

## 9. NPC 日程与时间

关键 NPC 不需要逐秒模拟。

使用：

```text
时间段
+
事件状态
+
NPC 当前状态
→ 当前地点 / 是否可交互
```

例如：

```text
上午：丹阁
下午：任务堂
夜晚：洞府
```

重大事件发生后，该日程可以被状态覆盖。

这样既让世界有“人在生活”的感觉，又避免复杂自主 Agent 模拟。

## 10. 锚点命运与一世变数

同一 Anchor 重复推演必须同时满足：

- 前世知识有价值。
- 下一世仍有新鲜感。

### 锚点命运

相对稳定：

- 核心人物身份。
- 重大事件根因。
- 重要传承是否存在。
- 关键时间窗口。
- 世界危机骨架。

### 一世变数

允许变化：

- 普通奇遇。
- 天气。
- 市场供给。
- 非核心 NPC 行动。
- 普通遭遇。
- 部分支线。

Knowledge 主要利用锚点命运；记录一世变数时，其适用性更容易变为“可能变化”。

## 11. 确定性随机

重大结果不能依赖全局顺序 RNG。

禁止：

```text
重大事件原本失败
→ 玩家多走 300 步
→ 随机序列被推进
→ 重大事件成功
```

重大结果应由有意义上下文决定，例如：

```text
AnchorFateSeed
+ EventId
+ DecisionId
+ 玩家关键状态
+ NPC关键状态
+ relevantStateHash
```

普通枝节可以使用：

```text
RunVariationSeed = hash(AnchorFateSeed, runNumber)
```

## 12. 战斗与风险

战斗不是高频刷怪系统，而是高价值风险解决器。

战斗目标：

- 决策数量有限但重要。
- 逃跑是正式结果。
- 受伤会产生后续内容。
- 准备、Knowledge、词条、功法和装备比纯随机更重要。

风险来源还包括：

- 中毒。
- 环境。
- 修炼失败。
- 社交冲突。
- 时间错失。
- 秘境陷阱。
- 寿元。

V0.1 不要求动作连招或大量战斗演出。

## 13. 死亡

死亡是跨世系统入口。

来源可包括：

- 战斗。
- 伤势恶化。
- 中毒。
- 走火入魔。
- 秘境灾害。
- 寿元终结。
- 主动坐化。

死亡本身不自动奖励词条。

重复用完全相同方式机械送死，应因为：

- 对应 Knowledge 已经获得。
- 没有新增人生事实。
- 词条代表性不增加。

而自然失去收益。

## 14. 熟悉状态与重复人生

熟悉状态由 Knowledge 与历世经历派生，不是独立 Meta 货币。

可用于：

- 已知安全地点快速旅行。
- 普通事件快捷处理。
- 已知路线摘要。
- 关键交互对象前世标记。
- 缩短重复文本。

原则：

> 第一世付出探索成本，后续人生应该越来越像“利用攻略改变未来”，而不是重复劳动。
