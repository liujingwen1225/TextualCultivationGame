# 诸世问道：修炼、事件与节奏系统

> 状态：当前有效基线

## 1. 设计目标

修仙成长必须有分量，但不能依靠现实挂机时间或超长经验条制造时长。

核心原则：

> 修炼推进游戏内时间，时间推动世界变化，世界变化反过来制造修炼选择。

## 2. 游戏内时间

所有长期行为消耗世界中的时间：

- 修炼。
- 闭关。
- 旅行。
- 宗门任务。
- 炼丹 / 炼器。
- 秘境探索。
- 养伤。

不使用“现实等待 8 小时后领取修为”的挂机模型。

例如：

```text
闭关 30 天
→ 世界时间 +30 天
→ 获得修为
→ 期间参与事件调度
→ 可能出现功法疑难、宗门召集、突破契机等变化
```

长时间行动不能成为跳过世界的无交互按钮。

## 3. 修为与境界

### 3.1 修为不是自动升级条

修为达到阈值，只表示取得突破资格。

突破还可以需要：

- 功法理解。
- 身体状态。
- 灵根 / 资质条件。
- 丹药或材料。
- 心境或特殊经历。
- 地点 / 环境条件。

### 3.2 突破事件化

突破通过事件或高层流程结算，允许多种结果：

- 成功。
- 失败但无严重后果。
- 受伤。
- 根基受损。
- 走火入魔。
- 获得特殊感悟。
- 打开隐藏成长路线。

重大突破不应只是一条“成功率 63%”的无上下文按钮。

## 4. 节奏指标

当前不规定：

- “首次筑基必须 15～30 小时”。
- “每个小境界必须 X 分钟”。
- “一世必须玩 X 小时”。

优先使用这些设计指标：

- 有效行动数量。
- 资源问题数量。
- 突破瓶颈数量。
- 关键事件密度。
- 重大选择频率。
- 一世内可验证的 Knowledge 数量。

基础目标：

- 通常 2～4 个重大行动后，应出现一次有意义变化。
- 原则上不要连续超过 5 个重大行动完全没有新交互或新信息。
- 重复内容达到熟悉状态后，可以快捷处理，减少机械重复。

最终实际节奏以可玩原型测试为准。

## 5. Event Pressure

Event Pressure 用于控制“什么时候应该让世界发生变化”，不是让玩家刷点击次数。

主要输入：

- 经过的游戏内时间。
- 当前地点事件密度。
- 当前剧情压力。
- 行动本身风险。
- 当前世界状态。
- 距离上一次重大事件的时间。
- 当前 Run 主题。

禁止简单设计：

```text
修炼 3 天 +12
修炼 3 天 +12
修炼 3 天 +12
```

导致拆成小动作比一次闭关获得数倍事件概率。

同样 30 天时间，无论玩家选择 `3天 × 10` 还是 `30天 × 1`，基础时间压力应大体同级，再由行动性质产生差异。

## 6. 事件调度

事件来源可以包括：

- 核心事件链。
- NPC 人物事件。
- 宗门事件。
- 地点事件。
- 奇遇。
- 秘境事件。
- 战斗风险。
- 修炼事件。
- 世界危机。

事件调度顺序建议：

```text
当前必须处理的强制事件
  ↓
关键事件链候选
  ↓
高相关人物 / 地点候选
  ↓
普通随机候选
  ↓
低价值填充事件
```

需要保留：

- 冷却。
- 重复衰减。
- 核心剧情保护。
- 长时间无事件时的保护机制。

但不要把这些设计成玩家可见的抽卡概率游戏。

## 7. 锚点命运与一世变数

同一个 Anchor 重复推演时，必须同时满足“前世知识有价值”和“下一世仍有新鲜感”。

因此分两层：

### 锚点命运

相对稳定：

- 核心人物真实身份。
- 重大事件根因。
- 重要传承是否存在。
- 某些关键时间节点。
- 世界级危机骨架。

### 一世变数

允许变化：

- 普通奇遇。
- 日常遭遇。
- 市场供给。
- 非核心 NPC 行动。
- 部分支线。
- 天气 / 环境细节。
- 同一问题的非关键过程。

Knowledge 主要利用锚点命运，也可以记录一世变数，但后者更容易变为“可能变化”。

## 8. 确定性随机

重大结果不能依赖一个全局顺序 RNG，让玩家通过做无关操作改变命运。

不允许：

```text
重大事件本来失败
→ 先做十次无关操作
→ RNG 序列推进
→ 重大事件成功
```

重大结果应由有意义上下文键决定，例如：

```text
Anchor Fate Seed
+ Event Id
+ 玩家关键状态
+ NPC关键状态
+ Decision Id
+ Attempt Context
```

普通一世变数可以使用 Run Variation Seed。

建议两层种子：

```text
AnchorFateSeed
= 绑定 Anchor 的关键命运

RunVariationSeed
= hash(AnchorFateSeed, runNumber)
= 控制当前一世的枝节变化
```

## 9. 战斗与风险

战斗不是高频刷怪系统，而是高价值风险事件。

战斗设计目标：

- 1～3 个核心决策节点可以形成一次有意义战斗。
- 逃跑是正式玩法结果，不是失败兜底。
- 受伤能够生成后续内容。
- 准备、Knowledge、词条和装备比纯随机更重要。

风险来源不仅有战斗：

- 环境。
- 中毒。
- 修炼失败。
- 社交冲突。
- 时间错失。
- 秘境陷阱。
- 寿元。

## 10. 死亡

死亡是跨世系统入口。

死亡来源可包括：

- 战斗死亡。
- 伤势恶化。
- 中毒。
- 走火入魔。
- 秘境灾害。
- 寿元终结。
- 主动坐化。

死亡本身不自动奖励词条。词条资格取决于这一世是否形成了足够鲜明的经历。

重复以相同方式机械送死，应通过：

- Knowledge 已获得。
- 词条条件不重复满足或代表性下降。
- 无新增成果。

自然降低收益。

## 11. 熟悉状态

熟悉度不再是独立 Meta 货币。

它是由 Knowledge、历世次数和已解决内容派生出的便捷状态，可以用于：

- 快速处理已知低风险事件。
- 显示额外提示。
- 缩短重复文本。
- 解锁“按前世经验处理”选项。

但不能与 Knowledge、词条并列形成第三套永久成长资源。
