# 诸世问道：核心游戏设计

> 状态：Steam 像素 RPG 重设计当前有效基线

## 1. 一句话定位

《诸世问道》是一款面向 Steam 的 **东方修仙像素人生模拟 Roguelite RPG**。

玩家直接控制一名普通修士，在可探索的像素修仙世界中移动、修炼、交友、调查、战斗和探索秘境；死亡后通过天衍锚点回到过去，保留对未来的 Knowledge，并利用前世经历不断改变命运。

核心卖点不是“死了读档”，而是：

> **我知道未来会发生什么，但当我改变过去之后，未来也会开始偏离。**

## 2. 产品边界

项目不做：

- 纯文字菜单游戏。
- 自由输入式 AI Dungeon。
- 《八方旅人》规模的高成本线性 JRPG。
- 《Project Zomboid》规模的万物模拟沙盒。
- 依赖常驻服务端才能运行的在线 RPG。

当前形态是：

```text
可探索像素世界
+
事件驱动叙事
+
角色成长 / 战斗
+
NPC 与世界状态
+
Anchor / Knowledge / 多世回溯
```

## 3. 四个设计支柱

### 3.1 前世知识必须真正改变今生

Knowledge 不是图鉴文本，而是可以用于行动的未来信息。

例如玩家前世发现：

```text
赵长青提供的灵酒有毒
```

下一世不只是多一段提示，而应该能够：

- 拒绝灵酒。
- 偷换酒壶。
- 提前准备解毒丹。
- 跟踪赵长青。
- 向其他 NPC 求证。
- 因提前干预而打开新的事件链。

### 3.2 地图负责沉浸，事件系统负责深度

玩家需要真实控制角色在地图中行动，但不把世界做成“所有物体都能模拟”的沙盒。

地图主要承担：

- 空间关系。
- 探索路径。
- 地点选择。
- NPC 接触。
- 风险区域。
- 场景氛围。

Event Engine 主要承担：

- 人物秘密。
- 条件事件。
- 连锁事件。
- Knowledge 选项。
- 词条选项。
- 因果变化。
- 世界状态变化。

同一个丹阁、洞府或山路，因为人生状态不同，可以出现完全不同的内容。

### 3.3 死亡必须产生信息或战略价值

死亡不是自动奖励。

一次有价值的一世至少应留下以下一种成果：

- Knowledge：获得未来情报。
- 承世候选：死亡时仍实际拥有的一项成果。
- 悟世条件：人生轨迹形成了可凝结词条。
- 路线验证：确认某个事件、人物或资源链的规律。

如果玩家出生后立即主动坐化，允许什么都得不到。

### 3.4 系统深度优先于资产数量

长期可玩性主要来自：

- 多 Anchor 路线选择。
- Knowledge 对未来的利用。
- 承世 / 悟世取舍。
- 词条 Build。
- 功法与突破路线。
- NPC 关系和秘密。
- 条件事件和事件链。
- 秘境风险。
- 锚点命运与一世变数。
- 新世界内容模块组合。

不是依靠大量地图、怪物和剧情动画堆量。

## 4. 核心循环

```text
选择已建立 Anchor
  ↓
配置最多 5 个词条
  ↓
进入一世
  ↓
在地图中移动 / 修炼 / 历练 / 社交 / 调查 / 战斗 / 探索
  ↓
地点事件 + NPC事件 + 条件事件 + 一世变数 + 重大命运
  ↓
Knowledge / 功法 / 装备 / 资源 / 人际结果
  ↓
突破 / 受伤 / 失败 / 死亡
  ↓
一世总结
  ↓
选择下一世 Anchor
  ↓
承世一项成果 OR 悟世一个词条
  ↓
消耗 1 次回溯
  ↓
下一世
```

如果角色仍存活并进入新的大境界，玩家可以选择“定世”，建立该大境界唯一的 Anchor。

## 5. 一世与一个世界

### 一世

从一个 Anchor 开始，到角色死亡结束。

退出游戏、回到主菜单、保存退出，都不会结束一世。

### 当前世界

从创建新世界开始，包含多世人生、多个 Anchor、Knowledge 与词条积累。

每个新世界基础拥有 **10 次回溯**。

当回溯次数已经为 0 时：

- 当前仍存活的一世继续正常游玩。
- 下一次死亡后当前世界结束。
- 玩家可以开始真正的新世界。

Steam 单机方向不采用旧方案中的账号级付费回溯额度。

## 6. 玩家决策必须有代价

### 死亡结算

```text
承世极品功法
VS
悟出长期词条
```

### Anchor 选择

```text
回炼气：可彻底改变早期路线，但需要重新成长
VS
回金丹：损失时间更少，但早期历史基本固定
```

### 定世

```text
现在固定一个稳定状态
VS
继续冒险争取更强状态，但可能死亡而永远失去这个锚点机会
```

### 唯一物

```text
继续承世唯一物
VS
放弃它换取更重要的能力
```

## 7. 世界探索原则

像素地图不是用来制造走路时长。

重复人生中已经熟悉的低风险路线可以逐步获得快捷能力，例如：

- 已知地点快速旅行。
- 已解决普通事件快速处理。
- 前世路线摘要。
- Knowledge 直接标记关键交互对象。

原则：

> 第一世强调发现，后续人生强调利用发现，而不是被迫重复走相同的路。

## 8. 战斗定位

战斗是高价值风险解决器，不是刷怪主循环。

首版战斗应：

- 小规模。
- 短时。
- 风险清晰。
- 准备和信息有价值。
- 逃跑是正式结果。
- 伤势会进入后续人生事件。

V0.1 不追求动作连招、弹幕或大量战斗演出。

## 9. AI 定位

AI 不是权威规则引擎。

允许用途：

- 一世评价文案。
- 事件文本润色。
- 内容生产辅助。
- NPC 表达变化。
- 开发、测试和资产概念辅助。

AI 不直接决定：

- 数值结算。
- 战斗胜负。
- Event Condition / Effect。
- 词条资格。
- Knowledge 真值。
- Anchor 快照。
- 唯一物状态。

所有权威状态必须由可测试代码和内容规则决定。

## 10. V0.1 唯一问题

V0.1 仍只回答：

> **“在真实可探索的像素 RPG 世界里，活一世 → 死亡 → 带着前世信息回来 → 改变命运”是否足够好玩？**

如果这条循环不成立，不继续扩展境界、开放世界、宗门经营、Steam 商业功能或大规模美术内容。
