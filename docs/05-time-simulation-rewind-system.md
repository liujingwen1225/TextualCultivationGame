# 诸世问道：时间、推演与回溯系统

> 状态：设计基线 V0.2  
> 依赖：`01-game-system-framework.md`、`02-v0.1-playable-prototype.md`、`03-event-content-specification.md`、`04-character-cultivation-system.md`  
> 目标：定义游戏日期、行动推进、天衍锚点、未来推演、死亡结算、跨世继承、世界线偏移与现实推进规则。

---

# 1. 核心定位

本项目中的“回溯”不是普通 Save / Load。

玩家真正进行的是：

> 从一个现实锚点出发，推演自己未来的一生；在失败、死亡或主动终止后，将部分认知带回现实，再利用这些认知改变下一次未来。

必须同时满足：

1. 同一个锚点下，未受干预的世界具有较高可复现性。
2. 玩家改变关键因素后，未来会产生真实偏移。
3. 推演中的物质收益原则上不能直接带回现实。
4. Knowledge / Insight 可以跨世保留。
5. 玩家最终必须推进现实，不能永远停在同一个锚点刷收益。
6. 回溯机制不能鼓励无脑重复死亡。

---

# 2. 时间单位

## 2.1 基础单位

最小规则时间单位：**天**。

不模拟小时和分钟。

日期结构：

```text
纪年 / 年 / 月 / 日
```

例如：

```text
青玄历 132 年 3 月 17 日
```

内部建议使用从世界纪元开始的 `dayIndex` 作为唯一计算基准，显示层再转换成年/月/日。

## 2.2 为什么用天

- 修仙玩法天然以天、月、年为尺度。
- 便于闭关与长期推进。
- 事件触发更稳定。
- 避免无意义的小时级模拟。

---

# 3. 时间推进原则

每个行动都必须声明 `timeCost`。

例如：

| 行为 | 示例耗时 |
|---|---:|
| 与 NPC 简短互动 | 0～1 天 |
| 宗门杂务 | 1～7 天 |
| 前往坊市 | 1 天 |
| 短期修炼 | 3～30 天 |
| 研读功法 | 7～90 天 |
| 小闭关 | 30～180 天 |
| 长闭关 | 1～数年 |
| 秘境 | 动态 |
| 突破 | 数日～数月 |

数值属于平衡参数。

---

# 4. 时间推进管线

任何系统不得自己随意修改日期。

统一经过：

```text
AdvanceTime(days)
```

执行顺序固定：

```text
1. 计算目标日期
2. 找出区间内的强制时间事件
3. 按时间顺序推进至最近事件
4. 更新角色年龄/寿元
5. 更新伤势和状态
6. 更新修炼/任务/冷却
7. 更新必要 NPC 状态
8. 触发世界事件
9. 处理玩家选择
10. 继续推进剩余时间
11. 到达目标日期
```

因此如果玩家选择闭关 2 年，而半年后宗门覆灭，系统不能直接跳过两年。

---

# 5. 事件中断

长时间行动必须支持三类事件：

## 强制中断

例如：

- 宗门遭袭
- 洞府被毁
- NPC 强制召见
- 玩家重伤恶化

必须停止当前行动。

## 可选中断

例如：

> 陆清瑶三个月后邀请玩家参加历练。

玩家可以：

- 出关
- 拒绝并继续闭关

## 忽略事件

已完全解决且无重大影响的低价值日常，可以汇总处理。

长期游玩必须避免闭关导致玩家错过所有世界内容，也避免每三天弹一次无意义事件。

---

# 6. 四层状态模型

```text
Content State
    ↓
Anchor State
    ↓ clone
Run State
    ↓ settlement
Meta State
```

## 6.1 Content State

开发者定义的基础世界：

- 日历
- NPC模板
- 事件模板
- 地点
- 功法
- 物品
- 世界规则

## 6.2 Anchor State

玩家真实世界在建立天衍锚点时的快照：

- 日期
- 主角状态
- NPC状态
- 关系
- 事件链进度
- 物品
- 地点
- 宗门身份
- 世界 flags

## 6.3 Run State

一次推演独立状态：

- 从 Anchor clone
- 只写当前推演
- 包含本世事件和资源
- 包含本世随机状态
- 包含本世 Knowledge / Insight 候选

## 6.4 Meta State

跨世永久保留：

- Knowledge
- Insight
- 诸世录
- 图鉴
- 天衍能力成长
- 已发现重大真相

---

# 7. 天衍锚点

## 7.1 定义

锚点是：

> 玩家当前真正世界状态的唯一推演起点。

V0.1 默认只有 **1 个锚点**。

不做任意存档槽。

## 7.2 建立锚点

建立时生成不可变快照：

```text
Anchor
├── anchorId
├── createdAtDay
├── playerSnapshot
├── npcSnapshots
├── relationshipSnapshots
├── inventorySnapshot
├── worldFlags
└── eventStates
```

推演不能修改 Anchor。

## 7.3 锚点覆盖

玩家推进现实并建立新锚点后，旧锚点默认失效。

这样形成不可逆推进感。

高境界以后是否开放多个锚点留到未来设计，不进入早期版本。

---

# 8. 开始推演

流程：

```text
检查是否允许推演
↓
扣除/记录天衍成本
↓
Clone Anchor → Run
↓
附加当前 Meta Knowledge / Insight
↓
初始化 deterministic seed
↓
进入推演
```

玩家在 Run 中经历的时间可以从数月到数十年。

现实锚点时间不变化。

---

# 9. 为什么同一未来可以复现

如果未来完全随机，前世知识会失去价值。

因此每个 Run 必须拥有一个**基础世界种子**。

```text
futureSeed = hash(anchorId + worldSeed)
```

在相同 Anchor、相同关键行为条件下：

- 固定世界事件时间基本一致
- 核心 NPC 初始决策倾向一致
- 关键秘境结构一致
- 重要随机结果保持稳定或落在窄区间

例如第一世知道：

> 133 年黑水秘境开启。

第二世不应无缘无故变成 140 年。

这才能产生“知未来”的游戏感。

---

# 10. 不允许传统随机 SL

如果相同锚点、相同操作每次都重新随机：

```text
突破失败
→ 回溯
→ 再点一次
→ 直到随机成功
```

整个 Roguelite 设计会崩溃。

因此规定：

> 同一锚点、相同关键状态、相同方案，应尽量得到稳定结果。

玩家想改变结果，必须改变至少一个有意义因素：

- 准备更好的资源
- 提升功法理解
- 治愈伤势
- 改变同行 NPC
- 更换突破方案
- 改变事件前置条件

不是“重新摇骰子”。

---

# 11. 命运判定 Key

关键判定可以使用：

```text
OutcomeSeed = hash(
  anchorSeed,
  eventId,
  playerRelevantState,
  decisionId,
  attemptContext
)
```

这样：

- 完全相同条件结果稳定。
- 玩家改变真实变量后结果可能改变。
- 开发者仍可保留适度随机感。

不要求所有普通小事件 deterministic，但**重大前世知识相关事件必须可推理**。

---

# 12. 世界线偏移 Divergence

## 12.1 定义

每个 Run 维护：

```text
Divergence: 0～100
```

表示本世相对于锚点下“基准未来”的偏移程度。

## 12.2 偏移来源

例如：

| 行为 | 偏移参考 |
|---|---:|
| 普通选择变化 | +0～2 |
| 提前得到资源 | +1～3 |
| 救下原本死亡 NPC | +5～15 |
| 杀死核心 NPC | +10～25 |
| 阻止重要事件 | +15～30 |
| 改变宗门级结果 | +20+ |

不是最终平衡值。

## 12.3 偏移不是惩罚

偏移越高，不是“玩家做错了”。

它代表：

> 玩家已经真正进入未知未来。

这是游戏进步。

---

# 13. Knowledge 可信度

未来情报不永久 100% 有效。

例如：

```text
Knowledge:
135 年秋魔宗将袭击青玄宗
baseConfidence = 95
```

当前 Run 世界线偏移变高后：

```text
effectiveConfidence = f(baseConfidence, divergence, dependencyChanges)
```

UI 可以展示：

- 极可信
- 可信
- 已有偏移
- 高度不确定
- 天机已变

不必默认展示精确百分比。

---

# 14. Dependency：情报依赖

比全局偏移更重要的是具体依赖。

Knowledge 可以记录：

```text
KNOWLEDGE_ZHAO_POISON
依赖：
- Zhao alive
- Zhao enters cave
- Zhao hostileToPlayer
```

如果玩家提前救了赵长青的家人，使其关系发生重大变化，系统可以直接判断：

> 原情报已经失效。

这比只看 `Divergence=42` 更合理。

---

# 15. 前世 Knowledge

Knowledge 是“具体事实认知”。

分类：

### 人物知识

> 赵长青会在洞府下毒。

### 地点知识

> 洞府第三层东侧石壁后存在阵眼。

### 时间知识

> 黑水秘境将在 133 年 4 月开启。

### 方法知识

> 解毒丹可以抵抗黑水散。

### 真相知识

> 丹阁陈执事并非真正的陈执事。

---

# 16. Knowledge 获得

获得条件必须由事件配置明确声明。

不是所有玩家看到的文本都会自动成为永久 Knowledge。

例如：

```text
玩家亲眼看到赵长青下毒
→ KNOWLEDGE_ZHAO_POISON
```

但：

> NPC 随口说“听说赵长青不是好人”

只能获得 Rumor，而非 Verified Knowledge。

后续可设计：

- 传闻
- 怀疑
- 已验证

V0.1 可以先只做已验证 Knowledge。

---

# 17. Insight

Insight 与 Knowledge 区别：

```text
Knowledge = 世界是什么
Insight   = 玩家学会了什么
```

例：

Knowledge：

> 第三层有杀阵。

Insight：

> 玩家对《基础阵解》的理解提升。

Insight 主要来自：

- 修炼
- 失败
- 突破
- 研读
- 特殊体验

用于下一世缩短重复成长过程。

---

# 18. Run 结束条件

推演可由以下方式结束：

## 死亡

- 战斗死亡
- 中毒死亡
- 寿尽
- 突破死亡
- 事件死亡

## 不可持续状态

某些情况下玩家没有立即死亡，但当前人生已经极差：

- 根基彻底损坏
- 被废修为
- 宗门覆灭且核心目标失败

玩家可以选择继续探索，也可以结束推演。

## 主动结束

允许，但存在约束：

- 不能在关键判定过程中瞬间退出规避损失
- 某些 Knowledge 只有经历完整结果后才获得
- 频繁无收益结束不会产生额外 Meta 奖励

---

# 19. 诸世结算

Run 结束后进入 Settlement。

展示：

```text
本世编号
模拟起止日期
模拟年龄
最高境界
关键人物关系
重大事件
死亡/结束原因
新发现 Knowledge
新获得 Insight
世界线最高偏移
抵达的最远未来
```

并永久写入《诸世录》。

---

# 20. Meta 提取规则

Run State 结束后：

## 默认不保留

- 境界
- 修为
- 灵石
- 丹药
- 法器
- 任务完成状态
- NPC 对玩家的关系变化

## 可以保留

- 明确获得的 Knowledge
- 符合条件的 Insight
- 诸世记录
- 图鉴发现
- 天衍能力相关资源

## 特殊例外

未来若存在真正能跨越推演带回物质的“天衍至宝”机制，也必须是极高价值特殊规则，不能成为常规系统。

---

# 21. 重复收益递减

防止玩家刷同一死亡：

```text
第一次因同一瓶颈失败
→ 高 Insight

第二次同因失败
→ 低 Insight

第三次无新信息
→ 几乎无 Insight
```

Knowledge 本身是唯一事实，不重复叠加。

玩家想获得新的跨世收益，需要：

- 走得更远
- 尝试不同方案
- 接触新人物
- 解开新秘密

---

# 22. “更远未来”奖励

长期 Roguelite 要鼓励玩家突破历史最远点。

Meta 可以记录：

```text
FurthestDayReached
```

第一次抵达新的年份/重大阶段时，可提供：

- 天衍资源
- 诸世成就
- 新系统提示

但不直接赠送大量修为。

玩家追求：

> “这一世我终于活到了以前没到过的地方。”

---

# 23. 现实推进：定世

这是系统必须有的一步。

如果只能永远回到 16 岁锚点，长期游戏会陷入重复。

因此玩家在满足条件后可以：

# 定世

含义：

> 将现实真正推进到一个新的稳定节点，并建立新的 Anchor。

---

# 24. 定世不是直接复制任意 Run

为了保持规则可信，不能简单：

> 我这世修到筑基 → 点按钮 → 整个 Run 状态复制成现实。

建议采用“确认现实路线”的方式。

玩家在 Run 中证明某条路线可行后，获得：

```text
Destiny Route / 已验证命途
```

现实可以执行该路线。

系统对已验证、低风险、重复步骤提供加速结算，但：

- 仍消耗现实时间
- 仍消耗现实资源
- 重大选择仍需确认
- 已受世界线变化影响的步骤可能需要重新处理

最终现实真正到达新节点后，才建立新 Anchor。

---

# 25. 为什么需要“现实路线”而不是直接复制

否则玩家可以在模拟中：

- 花掉所有资源
- 赌一个 1% 成功结果
- 成功后直接复制现实

这会失去修仙规划感。

正确体验应该是：

```text
模拟证明路线
↓
知道需要什么
↓
回到现实
↓
真正准备资源与关系
↓
执行路线
↓
现实前进
↓
建立新锚点
```

这使“推演”是信息优势，而不是作弊存档。

---

# 26. 定世的早期简化方案

V0.1 暂时不实现完整现实执行系统。

原型只需要：

```text
Anchor
→ Run
→ Settlement
→ 回 Anchor
```

正式进入长期版本前必须实现“现实推进/新锚点”。

否则不能开始扩展筑基以上内容。

---

# 27. 推演成本

不建议一开始把推演成本做成手游体力。

推演次数可以由世界观资源约束，例如：

> 天衍道蕴

但早期设计原则：

- 不强迫真实时间等待
- 不做每日次数恢复
- 不与付费绑定
- 主要用于限制无限即时回溯

获取来源：

- 抵达新的未来
- 发现重大 Knowledge
- 首次突破重要阶段
- 完成重大因果

V0.1 可以先不扣资源，只记录推演次数。

---

# 28. 玩家记忆与角色记忆

必须区分：

```text
Player Meta Memory
和
Current World Character/NPC Memory
```

玩家回溯后知道：

> 陆清瑶曾在上一世救过自己。

但当前时间线陆清瑶不知道。

因此不能直接恢复 NPC 好感。

这会产生：

> 玩家拥有感情，但 NPC 仍然陌生。

是后续人物系统的重要特色。

---

# 29. 跨世选项

Knowledge 的主要玩法价值不是显示图鉴，而是解锁新选择。

统一标记：

```text
★【前世记忆】
```

例如：

```text
1. 接过赵长青的丹药
2. 拒绝

★【前世记忆】提前服下解毒丹
★【前世记忆】假装中毒观察赵长青
```

不同 Knowledge 可以组合解锁更高级选项。

---

# 30. Knowledge 组合

长期内容应支持：

```text
Knowledge A
+
Knowledge B
+
能力条件
→ 新选项 C
```

例如：

```text
知道赵长青下毒
+
知道第三层阵眼
+
基础阵解 ≥ 2
↓
★ 故意利用赵长青触发外层禁制，再从阵眼进入密室
```

这让多世知识形成网络，而不是单线攻略。

---

# 31. 分支收敛

一个人开发不能维护指数级剧情树。

因此事件设计采用：

```text
局部分支
↓
状态差异
↓
重新汇入共享节点
```

例如玩家可以用三种方法避毒，但最终都进入：

> 古修洞府第二层。

区别通过：

- NPC关系
- 剩余资源
- 是否受伤
- Knowledge
- flags

保留下来。

避免写出无限剧情树。

---

# 32. 长期推演的内容密度

长期升级不能意味着长时间无事发生。

建议正式平衡目标：

- 小型有效反馈：每数分钟一次
- 有意义事件/决策：每 5～15 分钟一次
- 中型事件链推进：每 30～60 分钟至少一次
- 大型人生节点：每数小时一次

闭关数年可以“一次操作”完成，但期间用摘要、关键事件和中断展示，而不是让玩家实际等待。

---

# 33. 时间压缩展示

例如闭关三年：

```text
青玄历 132 年 → 135 年

闭关结算：
修为 +xxx
青木诀理解 +x
消耗聚气丹 x12

期间发生：
- 133年 黑水秘境开启（你选择不出关）
- 134年 韩石晋升内门
- 135年 师父传来急讯【强制中断】
```

长期时间尺度依然适合 Web 文字游戏。

必须实现：

- `dayIndex`

- 定时事件中断
- Anchor snapshot
- Run clone
- Run death/end
- Settlement

- Insight 持久化

# 35. V0.1 验收

- [ ] 同一个 Anchor 可以重复开始 Run。
- [ ] Run 修改不会污染 Anchor。
- [ ] 时间推进可以被关键事件中断。
- [ ] 角色死亡后进入 Settlement。
- [ ] 灵石/物品/境界恢复 Anchor 状态。
- [ ] Knowledge / Insight 保留到 Meta。
- [ ] 同条件重大事件结果可以稳定复现。

# 36. 长期版本的成功体验

最终玩家应经历：

```text
第一世
我用 12 年才走到这里，然后死了。

第二世
我知道了真正的问题，7 年就走到了这里。

第三世
我提前救下关键人物，只用了 5 年，
但这一次未来彻底变了。

第四世
我进入了过去从未见过的二十年。
```

这就是《诸世问道》时间系统真正要提供的东西：

> **不是无限重试，而是通过一次次人生，把未知逐渐变成理解，再主动踏入新的未知。**
