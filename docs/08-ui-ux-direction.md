# UI / UX 方向

## 1. 桌面优先

V0.1 以 Windows 键鼠为基线，后续再补手柄完整适配。

建议输入：

- WASD / 方向键：移动。
- E / Enter：交互 / 确认。
- Esc：返回 / 菜单。
- I：背包。
- C：角色 / 修炼。
- J：见闻 / 情报。
- M：地图。
- Space：战斗暂停 / 继续。

具体键位允许实现阶段调整，但不再使用移动端竖屏交互作为基准。

## 2. HUD

探索状态下保持克制：

- 气血。
- 法力。
- 当前境界。
- 游戏内时间。
- 当前地点。
- 临近交互提示。
- 必要的持续伤势 / 中毒提醒。

不常驻展示大量属性、任务和社交数值。

## 3. 角色 / 修炼界面

应能清晰回答：

- 当前境界和修为进度。
- 主修功法。
- 根骨 / 悟性 / 神魂 / 灵根 / 体质等关键资质。
- 气血 / 法力 / 神识派生状态。
- 寿元。
- 当前伤势。
- 已掌握术法与掌握度。
- 当前突破准备状态。

突破准备优先使用“不足 / 尚可 / 充分”等语义信息，而不是把所有隐藏机制数字化。

## 4. 见闻 / 情报

替代旧跨世 Knowledge 页面。

推荐信息组织：

```text
人物
地点
势力
事件
功法
资源
危险
```

条目可以显示：

- 当前已知事实。
- 来源。
- 传闻 / 推断 / 已验证。
- 关联人物 / 地点 / 事件。
- 当前可行动线索。

它不是主线任务列表，也不自动公布真相。

## 5. 机会视图

允许提供轻量“当前值得关注”的摘要：

- 三日后外门小比。
- 半月后黑水秘境开放。
- 某 NPC 最近行为异常。
- 某资源即将到货。

玩家可以忽略，不把它做成强制任务清单。

## 6. NPC 界面

核心 NPC 可以显示：

- 身份。
- 玩家当前对其关系的自然语言描述。
- 已知信息。
- 已确认的社会关系 / 势力。

内部可以有多维关系数值，但 UI 不默认显示五根精确进度条。

## 7. 战斗 UI

RTwP 战斗必须清晰表现：

- 当前是否暂停。
- 主角和目标状态。
- 行动 / 施法进度。
- 有威胁的敌方动作。
- 技能、法宝和消耗品快捷入口。
- 移动 / 距离 / 范围提示。
- 重要伤势和状态。

暂停时应支持检查战场并下达下一步指令。

## 8. 事件表现

重大事件不必切换到纯文字页面。

建议：

```text
保留当前场景背景
→ 摄像机 / 光照聚焦
→ NPC 立绘或像素角色强调
→ 文本与选择覆盖层
→ 结算后回到世界
```

事件 UI 服务场景沉浸，不把游戏重新变成视觉小说菜单。

## 9. 死亡界面

不再使用“一世终 / Anchor / 承世 / 悟世”。

死亡只需要：

- 明确死亡原因 / 关键伤势。
- 读取最近自动存档。
- 选择已有手动存档。
- 返回主菜单。

可以保留修仙风格表现，但不承担 Meta 玩法。

## 10. UI 设计原则

- 少而清楚。
- 重要信息明确，世界真相保留不确定性。
- 不为所有内部数值创建面板。
- 地图和场景优先，UI 不长期遮挡探索空间。
- 鼠标与键盘均能完成核心操作。
- 所有核心流程应支持自动化输入 / UI Smoke Test。
