# 诸世问道：完整游戏系统框架

> 状态：设计基线 V0.1  
> 目标：定义游戏是什么、核心循环如何成立、各系统如何协同，以及独立开发阶段的功能边界。

---

# 1. 游戏定义

## 1.1 类型

东方修仙题材的 **文字 Roguelite / 人生模拟 RPG**。

核心不是“AI 自动写小说”，也不是“天道视角世界模拟”，而是玩家扮演一名普通修士，在一次次未来推演中修炼、探索、建立关系、遭遇事件、失败和死亡，并将前世知识带回锚点，改写下一次未来。

## 1.2 核心幻想

玩家应持续获得四种体验：

1. **求长生**：寿元有限，必须在有限时间内寻找更高境界。
2. **知未来**：死亡不是纯损失，而是获得未来情报的渠道。
3. **改天命**：利用前世经验让原本不可避免的失败产生不同结果。
4. **走自己的路**：不同功法、人物、机缘和选择逐渐形成不同修行路线。

## 1.3 核心卖点

### A. 前世知识是真正的永久成长

装备、灵石和境界会随推演结束消失，但部分知识、情报和悟道会保留。

### B. 同一事件会因前世认知出现新选项

不是简单增加成功率，而是改变玩家可以做出的决策。

### C. 未来会被玩家改变

旧未来不是固定攻略。玩家越深入改变关键事件，原有未来情报越不可靠。

---

# 2. 设计原则

## 2.1 游戏规则高于叙事

任何影响真实状态的结果都必须由规则或内容配置决定，包括：

- 修为变化
- 灵石变化
- 物品获得与消耗
- 时间推进
- 寿元变化
- 关系变化
- 战斗胜负
- 事件是否触发
- 情报是否获得
- 是否死亡

AI 不拥有这些状态的最终写权限。

## 2.2 固定选择优先于自由输入

V0.1 不做自然语言自由行动。

玩家通过：

- 系统行动
- 事件选择
- 前世记忆特殊选项

完成游戏交互。

## 2.3 世界不做“大模拟”

第一阶段世界只需要对玩家相关内容保持一致，不模拟数千 NPC、完整经济、国家战争和全大陆历史。

## 2.4 内容必须数据驱动

事件、NPC、地点、物品、功法和奖励尽量从内容配置读取，避免把剧情硬编码在页面或业务代码中。

## 2.5 每个系统必须服务核心循环

如果某系统不能强化“推演 → 死亡 → 获得认知 → 回溯 → 改变未来”，默认不进入 V0.1。

---

# 3. 核心游戏循环

## 3.1 大循环

```text
现实/当前锚点
    ↓
开始推演
    ↓
行动与事件
    ↓
修炼 / 探索 / NPC / 资源
    ↓
时间流逝
    ↓
突破 / 失败 / 死亡
    ↓
诸世结算
    ↓
提取可继承知识
    ↓
回到锚点
    ↓
前世记忆解锁新选项
    ↓
历史发生偏移
    ↓
进入新的未知未来
```

## 3.2 小循环

一次普通行动：

```text
选择行动
  ↓
检查条件
  ↓
消耗时间/资源
  ↓
执行判定
  ↓
更新状态
  ↓
检查事件触发
  ↓
展示结果
```

## 3.3 关键体验节点

至少每 5–10 分钟应出现一次以下内容之一：

- 新事件
- 新人物信息
- 新地点
- 新功法/物品
- 明显风险
- 前世记忆提示
- 境界成长
- 时间压力
- 世界线变化

---

# 4. 游戏状态分层

游戏状态必须区分作用域，避免回溯逻辑混乱。

## 4.1 锚点状态 Anchor State

建立天衍锚点时冻结：

- 玩家属性
- 年龄与当前日期
- 当前境界与修为
- 当前地点
- 物品/灵石
- NPC 当时状态
- 关系状态
- 已发生世界事件
- 当前任务/事件链状态

每次新推演从锚点状态复制生成。

## 4.2 推演状态 Run State

只属于当前一世：

- 当前时间
- 当前角色状态
- 当前资源
- 本世人物关系
- 本世事件结果
- 本世伤势
- 本世死亡原因
- 本世新增情报

死亡/主动终止后该状态结束。

## 4.3 跨世状态 Meta State

不会随着回溯完全消失：

- 已知人物秘密
- 已知地点信息
- 已知事件情报
- 已知危险
- 已发现丹方/方法
- 部分功法理解
- 已完成诸世档案
- 天衍资源
- 成就/图鉴

## 4.4 内容状态 Content State

开发者定义、所有玩家共享的基础规则：

- 事件模板
- NPC 模板
- 地点模板
- 功法定义
- 物品定义
- 境界规则
- 掉落池
- 战斗规则

---

# 5. 时间系统

## 5.1 时间是核心资源

所有重要行动消耗时间。

建议最小时间单位：**天**。

无需模拟小时和分钟。

## 5.2 行动时间示例

| 行动 | 默认耗时 |
|---|---:|
| 普通修炼 | 3 天 |
| 宗门杂务 | 1–3 天 |
| 坊市往返 | 1 天 |
| 学习基础术法 | 7–30 天 |
| 小闭关 | 30 天 |
| 秘境探索 | 按事件动态推进 |
| 大闭关 | 1 年以上 |

实际数值后续平衡。

## 5.3 时间推进后统一处理

每次时间变化后按固定顺序运行：

1. 更新年龄。
2. 检查寿元。
3. 更新伤势/状态持续时间。
4. 更新冷却。
5. 推进定时事件。
6. 检查新的条件事件。
7. 更新 NPC 简化状态。
8. 判断是否需要强制事件。

保证所有系统对时间的理解一致。

# 6. 寿元系统

## 6.1 寿元不是装饰属性

寿元必须真正限制玩家。

```text
当前年龄：61
寿元上限：92
剩余预期寿元：31 年
```

## 6.2 境界的最大价值之一是延寿

境界突破应显著提高寿元上限，使“突破”成为生存需求，而不是单纯数值升级。

V0.1 仅需实现：

- 当前年龄
- 寿元上限
- 自然死亡
- 筑基后的寿元提升

## 6.3 寿元相关事件

后续可扩展：

- 延寿丹
- 暗伤折寿
- 燃烧寿元秘法
- 命格影响寿元

但不进入首个原型核心。

# 7. 角色系统

## 7.1 核心属性

V0.1 控制属性数量，建议：

- **灵根**：决定属性功法适配。
- **悟性**：学习、理解、悟道相关。
- **体魄**：生存、炼体、部分战斗判定。
- **神识**：感知、阵法、部分特殊事件判定。
- **气运**：只做少量隐藏权重，不成为万能幸运值。

## 7.2 动态状态

- 修为
- 生命/伤势
- 灵力
- 年龄
- 寿元
- 境界
- 当前状态效果

## 7.3 初始资质

第一版不需要复杂捏人。

建议采用：

- 固定主角模板，保证内容可控；或
- 3 个预设出身供选择。

不建议第一版随机生成数十种天赋。

---

# 8. 境界与修炼系统

## 8.1 V0.1 境界范围

```text
炼气一层
...
炼气九层
↓
筑基初期
```

第一阶段只验证“成功筑基”即可。

## 8.2 修炼收益

统一由规则计算：

```text
修炼收益
= 基础收益
× 功法适配
× 灵根适配
× 地点灵气
× 当前状态
```

无需一开始追求复杂数学模型。

## 8.3 突破条件

至少包含：

- 修为达到要求
- 当前状态允许
- 满足必要资源/功法要求
- 进行突破判定

## 8.4 突破结果

不只成功/失败，可预留：

- 完美成功
- 普通成功
- 失败
- 受伤
- 根基受损
- 死亡

V0.1 可先只实现成功、失败受伤、死亡三类。

---

# 9. 功法系统

每部功法定义：

- ID
- 名称
- 品阶
- 属性
- 境界限制
- 基础修炼效率
- 灵根适配规则
- 特性
- 学习条件
- 来源

V0.1 只需要 3–5 部功法。

## 9.1 功法理解

功法不仅有“是否获得”，还应有理解/熟练信息。

该数值可以部分进入跨世状态，使前世修行经验具备永久价值。

---

# 10. 地点系统

采用 **节点式地图**，不做自由移动地图。

V0.1 示例：

```text
青玄宗
├─ 外门
├─ 藏经阁
├─ 丹阁
└─ 后山

青石坊市

黑水山脉
└─ 黑水秘境
```

地点定义：

- 可进入条件
- 移动耗时
- 可用行动
- 可见 NPC
- 可触发事件
- 环境修炼系数

---

# 11. 行动系统

玩家在非事件状态下通过固定行动推进游戏。

V0.1 行动集合：

- 修炼
- 闭关
- 前往地点
- 与 NPC 互动
- 查看/学习功法
- 使用物品
- 接取/执行宗门任务
- 进入秘境
- 尝试突破

行动本质上统一成：

```text
Action
├─ 前置条件
├─ 时间消耗
├─ 资源消耗
├─ 判定
├─ 状态变化
└─ 后续事件检查
```

这样后续新增炼丹、炼器、采药时不需要改变底层模型。

---

# 12. 事件系统

事件系统是本项目最重要的内容承载层。

## 12.1 事件组成

一个事件必须至少包含：

- 触发条件
- 展示正文
- 可用选项
- 选项条件
- 结果效果
- 解锁情报
- 后续事件

## 12.2 事件类型

### 固定事件

特定时间必然发生。

### 条件事件

满足条件后进入候选池。

### 随机事件

在指定地点、行为或时间段按权重触发。

### 事件链

多个事件组成可跨越多年的连续因果。

### 前世记忆事件

只有 Meta State 中存在对应情报时才出现特殊选项。

---

# 13. 前世知识系统

这是项目的核心差异化系统。

## 13.1 Knowledge 类型

建议分为：

- **人物情报**：身份、秘密、立场。
- **事件情报**：未来时间、发生条件。
- **地点情报**：秘道、陷阱、隐藏区域。
- **方法情报**：解毒、破阵、特殊处理方式。
- **修炼认知**：功法理解、突破经验。

## 13.2 情报必须具有玩法效果

禁止只作为“百科文本”存在。

至少应产生一种效果：

- 解锁新事件选项
- 提前触发准备行动
- 降低风险
- 改变 NPC 交互
- 改变事件结果
- 提高某类判定

## 13.3 前世选项视觉规则

统一标识，例如：

```text
★【前世记忆】提前服下解毒丹
```

使玩家明确感知跨世成长。

---

# 14. 世界线偏移系统

## 14.1 目的

阻止游戏变成“第一世拿攻略，第二世照抄通关”。

## 14.2 偏移来源

改变关键事件会增加偏移：

- 救活原本会死的关键 NPC
- 杀死关键 NPC
- 提前获得重要传承
- 阻止大型事件
- 改变人物阵营

## 14.3 情报可信度

未来类情报可以拥有：

- 原始可信度
- 当前可信度
- 已失效状态

偏移增加后，系统降低部分未来情报可信度。

第一版不需要复杂公式，只需实现关键事件可直接使关联情报失效。

---

# 15. NPC 系统

V0.1 不做完整 Agent。

## 15.1 NPC 分层

### 核心 NPC

8–12 名。

保存：

- 身份
- 境界
- 性格标签
- 当前关系
- 秘密
- 当前事件状态
- 关键记忆

### 普通 NPC

只作为商人、执事、路人等功能角色，无长期自主模拟。

## 15.2 关系维度

V0.1 建议只做三项：

- 亲近
- 信任
- 戒备

后续再扩展利益、敬畏、仇恨等维度。

## 15.3 NPC 状态推进

NPC 不需要每天独立运行。

只在：

- 时间跨过关键节点
- 玩家所在事件涉及 NPC
- 事件链需要推进

时更新即可。

---

# 16. 因果系统

东方修仙特色系统，但 V0.1 只做轻量版本。

因果记录示例：

```text
人物：陆清瑶
类型：救命之恩
强度：40
状态：未了
```

因果可以成为：

- NPC 决策修正
- 特殊事件条件
- 后期心魔/天劫素材

V0.1 只需要记录并用于少量事件解锁，不做完整“天道因果计算”。

---

# 17. 物品与资源系统

V0.1 只保留服务决策的资源：

- 灵石
- 丹药
- 符箓
- 法器
- 关键任务物品
- 秘境材料

物品支持：

- 获得
- 消耗
- 携带
- 使用条件
- 事件条件检查

不做重量、耐久、品质随机词条等系统。

---

# 18. 战斗系统

第一版采用轻量自动判定，不做回合制战斗界面。

战斗输入：

- 玩家境界
- 关键属性
- 功法/法器
- 状态
- 敌人等级
- 场景修正

输出：

- 胜利
- 负伤胜利
- 逃脱
- 失败
- 死亡

战斗首先是事件的一种判定方式，而不是独立大系统。

后续若战斗本身证明需要深度，再升级为完整回合制。

---

# 19. 天衍锚点与回溯系统

## 19.1 锚点

锚点保存完整 Anchor State。

前期同一时间只允许一个有效锚点。

## 19.2 开始推演

创建 Run State：

```text
Run State = Anchor State 的可变副本 + Meta State 可用知识
```

## 19.3 模拟结束条件

- 死亡
- 寿元耗尽
- 特殊失败
- 玩家主动终止（后续可开放）

## 19.4 回溯

回溯后：

恢复 Anchor State。

合并本世允许继承的 Meta State。

绝不直接保留：

- 灵石
- 物品
- 境界
- 本世肉身状态

---

# 20. 诸世结算系统

每一世结束必须生成结构化档案，而不是只有一段 AI 总结。

至少记录：

- 推演编号
- 起始与结束年龄
- 存活时间
- 最高境界
- 死亡原因
- 重要事件
- 重要人物关系
- 新获得知识
- 新获得悟道
- 世界线偏移

这些数据组成《诸世录》。

AI 可以在结构化数据基础上生成“这一世”的文学化传记，但不作为唯一记录。

---

# 21. 宗门系统

V0.1 玩家作为宗门成员，不做经营。

只实现：

- 身份等级
- 宗门贡献
- 可进入区域
- 可学习功法
- 宗门任务
- 核心 NPC 关系

成长示例：

```text
杂役/记名
↓
外门
↓
内门
```

V0.1 不需要做到真传、长老和掌门。

---

# 22. 秘境系统

秘境是验证“死亡获得知识”的最佳场景。

## 22.1 结构

采用节点/事件链：

```text
入口
↓
外层
↓
岔路
↓
古修洞府
↓
杀阵
↓
核心传承
```

## 22.2 核心玩法

第一次不知道危险。

死亡后获得：

- 路线
- 陷阱
- NPC 背叛
- 解法

下一世使用前世知识深入更多区域。

V0.1 应至少有一条 3 世以上才能完整破解的秘境事件链。

---

# 23. AI 系统边界

## 23.1 V0.1 可以不依赖运行时 AI

所有核心事件必须有可用基础文本。

## 23.2 AI 适合做

- 事件结果润色
- NPC 对话变体
- 战斗描述
- 本世传记
- 内容生成辅助
- 开发期事件一致性检查

## 23.3 AI 不允许做

- 自己生成奖励数值并直接写入存档
- 自己决定突破成功率
- 自己决定获得不存在的物品
- 自己改变 NPC 隐藏真实状态
- 绕过事件条件

## 23.4 后续可选扩展

当固定选择版本已经证明好玩后，再评估：

- NPC 半自由对话
- 高级自由行动
- 动态支线生成

这些都不属于首要玩法。

---

# 24. 内容生产系统

对独立开发者而言，这是长期效率核心。

需要最终形成统一内容模型：

```text
World Content
├─ locations
├─ npcs
├─ events
├─ event chains
├─ items
├─ techniques
├─ enemies
└─ knowledge
```

原则：

> 新增一条事件链应主要新增配置与文本，而不是改游戏引擎代码。

后续再制作内部事件编辑器。

# 29. 产品成功判定

V0.1 不以“系统多少”判断成功，而以玩家是否产生以下心理：

> “我现在知道上一世为什么死了，我想再来一次看看能不能改掉。”

核心指标可以先观察：

- 首次死亡后是否立即开始第二世
- 第二世是否主动使用前世选项
- 玩家是否理解哪些内容会跨世保留
- 第三世是否仍有继续探索欲望
- 玩家能否讲出自己经历的不同时间线

如果这一循环不好玩，则暂停扩展炼丹、炼器、宗门经营等外围系统。
