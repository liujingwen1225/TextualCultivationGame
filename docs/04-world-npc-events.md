# 世界、NPC、事件与经济设计

## 1. 世界结构

正式世界采用开发者预制内容模块组合，而不是运行时 AI 即兴生成整个游戏。

基础结构：

```text
World
├─ Region
│  ├─ Map
│  │  ├─ Zone
│  │  ├─ Interaction Point
│  │  ├─ NPC Spawn / Schedule
│  │  └─ Event Pool
│  └─ Faction / Sect / Clan
├─ Important NPC
├─ Secret Realm
├─ Event Chain
└─ Long-term World State
```

当前阶段不实现完整程序化世界生成。

## 2. 地图

地图承担：

- 真实移动与空间关系。
- 地点选择。
- NPC 与设施入口。
- 调查与资源点。
- 环境风险。
- 战斗空间。
- 氛围表现。

不追求：

- 每个家具都可交互。
- 巨型无缝开放世界。
- 所有路人完整人生模拟。
- 建造沙盒。

## 3. 世界时间

有意义行动推进世界时间：

```text
本地调查 / 重要交谈 → 分钟 / 小时
采集 / 短途行动      → 小时 / 半日
跨区域旅行            → 小时 / 天
疗伤 / 炼制 / 修炼    → 天 / 月
闭关                  → 月 / 年
```

站立、菜单、普通房间移动、渲染帧不推进重大世界时间。

长时间行为必须让世界事件继续调度。

## 4. NPC 模型

重要 NPC 至少具有：

- 公开身份。
- 当前状态。
- 短期 / 中期目标。
- 资源与能力。
- 重要关系。
- 底线 / 风险偏好。
- 隐藏信息或秘密（按角色需要）。
- 时间段 / 事件状态驱动的地点安排。

NPC 行为由：

```text
目标
+ 资源
+ 关系
+ 世界状态
+ 时间
→ 当前行为
```

共同决定。

不使用运行时 LLM Agent 作为权威 NPC 决策器。

## 5. NPC 不等待玩家

NPC、秘境、宗门和地区事件可以在玩家修炼或旅行期间继续推进。

玩家错过某个时间窗口后：

- NPC 可能已经离开、受伤、突破或死亡。
- 秘境可能关闭。
- 资源可能被别人取得。
- 宗门政治可能改变。

时间因此是真正战略资源。

## 6. 人物关系

核心关系不是单一好感度。

可使用：

```text
亲近
信任
利益绑定
畏惧
仇恨
```

等内部维度表达不同关系意义，但 UI 优先转化成自然描述，避免大量进度条。

人物可以既真心喜欢玩家，又在利益或宗门义务下与玩家冲突。

师父、长老、同门不天然可信，也不默认都是阴谋家。

## 7. 社会身份

玩家同时拥有制度性身份，例如：

- 青玄宗外门弟子。
- 丹阁学徒。
- 某长老记名弟子。
- 家族客卿。
- 黑市熟客。
- 通缉犯。

身份影响地点权限、资源、价格、NPC 态度、任务和风险。

## 8. 宗门、家族与散修

宗门权力来自真实资源：

- 灵脉。
- 高阶功法与传承。
- 突破资源。
- 丹师 / 炼器师。
- 秘境名额。
- 安全环境。
- 高阶修士保护。
- 情报与商路。

加入宗门意味着：

```text
资源与保护
↕
规则、任务、派系与义务
```

散修是完整可玩路线：自由度高，但资源稳定性、情报与安全性较差。

家族是正式版重要势力类型之一，但当前 V0.1 不做家族经营。

## 9. 高阶修士的政治威慑

高阶修士不只是“等级高的 NPC”，而是地区秩序的重要政治资产。

某位金丹坐镇可以抑制敌对势力、保护商路和附属家族；其死亡可能改变战争、价格、地盘和 NPC 决策。

## 10. 经济基本原则

### 灵石

灵石既是交易媒介，也是现实修炼 / 阵法 / 法器等资源。

有钱不能直接解决所有修炼问题。

### 宗门功勋

功勋 / 善功是组织内部权限凭证，用于兑换宗门控制的名额、传承或资源，不是第二种万能货币。

### 稀缺性

境界越高，核心资源越难用普通市场购买：

```text
炼气：灵石、丹药、法器、普通术法
筑基：筑基法门、突破灵物、高品质灵脉、师承
更高：稀有天地灵物、核心传承、高阶洞府、特殊时机
```

## 11. 坊市

坊市不是无限库存商城。

供给可由：

```text
常规商品
+ 周期库存
+ 特殊商人
+ 拍卖 / 私下交易
+ 黑市
+ 世界事件状态
```

构成。

## 12. 经济模拟深度

采用状态驱动经济，不模拟全世界逐个 NPC 的生产运输消费。

示例：

```text
秘境开放
→ 解毒丹需求上升
→ 价格 / 库存变化

宗门冲突
→ 疗伤丹、符箓需求提高
```

主要输入：世界事件、地区状态、资源池、商人状态。

## 13. 修士生计

世界需要能够解释普通修士为什么能生活：

- 宗门弟子：月例、任务、职责。
- 散修：护送、采药、猎妖、制符、交易。
- 丹师 / 阵师 / 炼器师：专业服务。
- 家族修士：灵田、商路、产业和地盘。
- 坊市修士：经营、鉴定、护卫。

不要求每种职业都成为玩家复杂生产系统。

## 14. 情报 / 见闻系统

情报是角色当前人生中的知识，而不是跨死亡 Meta 记忆。

可以记录：

- 人物秘密。
- 地点危险。
- 资源位置。
- 功法隐患。
- 势力关系。
- 事件时间窗口。
- 敌人习惯与弱点。

情报可以标记来源与可信程度，例如：

```text
传闻
推断
已验证
```

多个线索可以支持新的调查选项或推论，但系统不需要自动公布最终真相。

信息页面更像“见闻 / 情报簿”，而不是传统主线任务日志。

## 15. Event Engine

事件由结构化数据描述：

```text
Trigger
+ Condition
+ Choice
+ Effect
```

常见 Trigger：

- ENTER_ZONE
- INTERACT_NPC
- INTERACT_OBJECT
- TIME_ADVANCED
- CULTIVATION_FINISHED
- COMBAT_FINISHED
- ITEM_ACQUIRED
- NPC_STATE_CHANGED
- WORLD_STATE_CHANGED

Condition 可以检查：境界、地点、时间、关系、身份、情报、物品、事件状态和世界状态。

Effect 应通过类型化规则修改权威状态，不允许内容脚本随意直接修改 SaveGame。

## 16. 事件结果与随机

重大结果不能被多走几步、打开背包、帧率或无关操作改变。

随机应按事件上下文或作用域管理，使测试可复现，同时保留普通遭遇、天气、市场供给等合理变化。
