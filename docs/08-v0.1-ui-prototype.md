# 诸世问道：V0.1 桌面交互与界面设计

> 状态：Steam 像素 RPG 重设计当前有效基线
>
> 本文档定义 V0.1 桌面像素游戏的交互结构、HUD、事件界面和轮回结算流程。具体美术语言见 `09-ui-visual-style-guide.md`。

## 1. 设计目标

V0.1 不再是移动端页面应用。

玩家的主要状态是：

> **在世界里控制角色行动。**

UI 应服务场景，而不是让玩家长期停留在菜单。

核心体验：

```text
移动角色
→ 进入地点 / 接触 NPC / 调查
→ 事件或战斗
→ 获得信息与成果
→ 继续探索
→ 死亡
→ 一世总结
→ Anchor / 承世 / 悟世
→ 开始下一世
```

## 2. 首发输入

P0：键鼠。

建议默认：

```text
WASD / 方向键  移动
E / Enter       交互 / 确认
Esc             返回 / 系统菜单
I               背包
C               角色
K               Knowledge / 前世记忆
M               地图
Tab             快捷信息 / 目标摘要
```

鼠标：

- 菜单。
- 事件选择。
- 背包 / 装备。
- 地图标记。

手柄在 V0.1 后期补齐，但 UI 结构从一开始避免依赖“鼠标悬停才看得到”的关键信息。

## 3. 常驻 HUD

默认 HUD 保持克制。

建议：

```text
┌────────────────────────────────────────────┐
│ 境界 / 气血 / 灵力              时辰 / 日期 │
│                                              │
│               游戏世界                       │
│                                              │
│                                              │
│ [E] 与陈执事交谈                             │
│                              回溯 8/10        │
└────────────────────────────────────────────┘
```

常驻信息只保留：

- 气血 / 灵力等即时状态。
- 当前境界。
- 游戏内时间。
- 回溯剩余次数。
- 当前可交互提示。

灵石、复杂属性、关系值等放在二级界面。

## 4. 地图交互

### 4.1 交互类型

场景内可交互对象分为：

- NPC。
- 门 / 区域入口。
- 调查点。
- 资源点。
- 修炼点。
- 商店 / 服务点。
- 秘境 / 危险入口。

### 4.2 视觉提示

不使用满屏发光轮廓。

推荐：

- 靠近后显示小型交互标识。
- 关键 Knowledge 对象显示青玉色前世标记。
- 高危险区域使用环境氛围和少量警示，不直接泄露完整结果。

例如：

```text
[E] 饮下灵酒

★ 前世记忆：你曾因这壶酒中毒而死
```

## 5. 地图与快速旅行

第一世以探索为主。

已经真实到达并确认安全的地点可以逐步解锁快速旅行。

快速旅行必须推进游戏内时间，并参与事件调度。

不能：

```text
点击地图
→ 无时间成本瞬移
→ 绕过所有世界变化
```

## 6. 事件界面

重大事件进入专门的事件表现层，但不需要切成完全独立的“手机页面”。

推荐形式：

```text
游戏场景保持在背景
↓
镜头轻微聚焦 / 暗化
↓
事件标题 + 角色立绘 / 像素角色
↓
事件正文
↓
可选项
```

选项类型：

- 普通选项。
- 条件选项。
- Knowledge 选项。
- 词条选项。
- 功法 / 物品选项。
- 高风险选项。

Knowledge 选项明确使用独立标识：

```text
★ 前世记忆
```

但不要直接把完整未来结果告诉玩家。

## 7. 对话设计

普通 NPC 服务对话应轻量，避免每次购物都进入高仪式感事件页面。

分两类：

### 普通交互

- 商店。
- 问候。
- 简短询问。
- 功能服务。

### 事件对话

- 关键人物冲突。
- 人物秘密。
- Knowledge 干预。
- 重大选择。
- 人物线推进。

只有后者使用完整事件表现。

## 8. 角色界面

角色菜单建议包含：

```text
角色
功法
装备
背包
词条
Knowledge
```

### 角色

- 境界 / 修为。
- 年龄 / 寿元。
- 气血 / 灵力 / 伤势。
- 核心资质。
- 身份。

### 功法

- 当前主修。
- 已掌握功法。
- 理解程度。
- 使用条件。
- 特殊规则能力。

### 装备 / 背包

必须清晰标识：

- 使用条件。
- 是否唯一物。
- 是否可承世。
- 当前耐久 / 数量等必要状态。

### 词条

显示：

```text
本世装备 3 / 5
```

词条库可超过 5 个，但进入一世后不能随意更换当前 Build。

## 9. Knowledge 界面

Knowledge 是未来记忆库，不是任务列表。

推荐分类：

```text
人物
地点
危险
资源
事件
秘密
```

每条显示：

- 记忆内容。
- 来源世数。
- 当前适用性。
- 已知关联地点 / NPC。

状态：

- 仍可信。
- 可能变化。
- 已失效。
- 矛盾。

如果 Knowledge 对当前地图对象有直接关系，可以在地图 / 交互层显示前世标记。

## 10. 战斗界面

V0.1 战斗 UI 以可读性和测试性优先。

无论最终采用回合制、时间轴或极简即时制，都必须清楚显示：

- 玩家状态。
- 敌人状态。
- 当前技能 / 行为。
- 伤势 / 异常状态。
- 逃跑入口。
- Knowledge / 词条造成的特殊战斗信息。

不以复杂 HUD 和大量技能栏制造深度。

## 11. 死亡表现

死亡是核心情绪节点。

建议流程：

```text
角色死亡
↓
场景声音 / 颜色逐渐收束
↓
“第 X 世终”
↓
进入一世总结
```

不要直接弹出传统：

```text
GAME OVER
[读取存档]
```

因为死亡不是传统失败。

## 12. 一世总结

建议结构：

```text
第 七 世 终

享年：23
最高境界：炼气四层
死因：黑水洞杀阵

【此世大事】
· 拜入青玄宗
· 发现黑水毒酒
· 深入黑水秘境
· 死于杀阵

【获得 Knowledge】
· 黑水洞第二层存在杀阵

【可承世成果】
...

【可悟词条】
...
```

重点是人生轨迹，不做纯统计结算屏。

## 13. Anchor 选择

死亡总结后进入 Anchor 选择。

表现应像“人生时间节点”，而不是普通存档列表。

V0.1 只有：

```text
炼气 Anchor
16 岁
青玄宗外门
```

正式版本可以沿时间轴 / 命轮展示多个大境界 Anchor。

Anchor 不提供覆盖、删除、修改。

## 14. 承世 / 悟世

选择 Anchor 后二选一。

### 承世

偏实体成果：

- 功法卷轴。
- 法宝。
- 装备。
- 丹药。

### 悟世

偏人生凝结：

- 命格纹章。
- 词条。
- 经历原因。

二者必须视觉和语义明显不同。

## 15. 下一世准备

结算完成后进入短暂准备阶段：

```text
下一世 Anchor
承世成果（若有）
词条装配 3 / 5
剩余回溯 7 / 10
```

确认后重新进入像素世界。

这一刻要有明确“回到过去”的视听反馈。

## 16. 系统菜单

Esc：

```text
继续游戏
保存并退出
设置
帮助
返回主菜单
```

“主动坐化”不放在高频 HUD。

建议：

```text
角色 / 系统菜单
└─ 特殊行动
   └─ 主动坐化
```

并要求二次确认。

## 17. V0.1 桌面 UI 验收

1. 不打开菜单也能完成移动与场景交互。
2. HUD 不遮挡主要探索区域。
3. Knowledge 相关交互一眼可辨。
4. 事件选择可同时支持键盘和鼠标。
5. 死亡后能连续完成“一世总结 → Anchor → 承世/悟世 → 词条配置 → 下一世”。
6. 保存退出不会触发死亡或回溯。
7. 重复人生中已知路线可以减少机械操作。
8. UI 支持 16:9 桌面优先，不按移动竖屏逻辑设计。
9. 所有关键交互都可被自动输入 / 测试工具触发。
10. V0.1 不因高保真 UI 阻塞核心玩法验证。
