# 当前项目状态

> 分支：`redesign/orthodox-cultivation-rpg-docs`

## 1. 当前产品结论

产品方向已经从“东方修仙像素人生模拟 Roguelite RPG”切换为：

> **东方修仙人生模拟 RPG**

核心目标是把“修仙人生本身”做成立，而不是依赖死亡回溯 Meta 循环制造差异化。

## 2. 已锁定

- 平台：Steam / Windows 优先。
- 引擎：Godot 4.7.x .NET。
- 语言：C#。
- Runtime：.NET 8。
- 表现：纯 2D 像素地图。
- 架构：本地权威运行时。
- Game Core：纯 C#，不依赖 Godot Scene / Node。
- 战斗：当前地图 RTwP 战术战斗。
- 玩家完全控制主角，盟友采用简化战术。
- 修炼消耗游戏内时间。
- 世界事件和重要 NPC 不等待玩家。
- 境界必须有质变和社会意义。
- 修真社会包含宗门、家族、散修、坊市和高阶修士威慑。
- 情报 / 调查是当前人生中的正式玩法系统。
- V0.1 使用沈川 + 青玄宗 / 青石坊市 / 黑水山 / 黑水秘境连续人生纵切。
- 自动化测试必须覆盖 Core、Scenario、Headless 和基础视觉/输入 Smoke。

## 3. 已删除

以下系统不再属于当前产品：

- Anchor / 天衍锚点 / 定世。
- 10 次回溯和死亡后重开人生。
- 承世。
- 悟世。
- 跨世 Trait。
- 跨世 Knowledge。
- 强制黑水三世结构。
- World Fate / 结世 / 跨 World Meta 作为当前主循环。
- 唯一物跨时间线规则。

技术方向同步删除：

- libGDX 候选与 Engine Spike。
- H5 / uni-app x / 小程序首发。
- Spring Boot + REST 单机玩法运行时。
- PostgreSQL + MyBatis-Flex 首版本地存档。
- LiteFlow 核心流程编排。

## 4. 仍需继续设计

产品与系统层仍需在进入 Spec 前收口：

- V0.1 黑水事件具体人物与隐藏真相。
- V0.1 功法 / 术法 / 法宝最小内容清单。
- RTwP 的具体动作时间、暂停规则、移动与攻击交互。
- 炼气阶段成长节奏。
- 普通 Save / AutoSave 的具体策略。
- 内容文件格式与编辑工作流。
- Godot 场景结构和地图资产约定。
- Scenario Runner 的命令与诊断输出格式。

这些是设计问题，不意味着需要现在生成 Spec / Tickets。

## 5. 当前开发禁令

在设计与架构收口前：

- 不生成正式 V0.1 Spec。
- 不生成实施 Tickets。
- 不开始正式 V0.1 功能开发。
- 不复用旧多世回溯 Issues 作为当前任务。
- 不为了未来可能需求创建 Anchor / Meta / World Generation 等抽象层。
- 不扩大 V0.1 地图和内容规模。

允许：

- 文档一致性清理。
- 产品/玩法设计收口。
- 运行时架构审查。
- Godot 工程架构设计。
- 内容数据和测试架构设计。
- 必要的极小技术验证，但不能伪装成正式开发。

## 6. V0.1 当前定位

V0.1 是一个连续的炼气修士人生片段：

```text
宗门生活
→ 发现黑水机会
→ 调查
→ 时间 / 资源取舍
→ 坊市准备
→ 黑水探索
→ RTwP 战斗
→ 秘境
→ 发现隐藏真相
→ 返回宗门
→ 后果持续存在
```

V0.1 不实现筑基完整层，也不实现世界级终局。
