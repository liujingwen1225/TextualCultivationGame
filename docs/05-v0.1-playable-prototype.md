# 诸世问道：V0.1 Steam 像素可玩原型

> 状态：Steam 像素 RPG 重设计当前有效开发基线
>
> V0.1 的目的不是完成完整修仙游戏，而是验证“可探索像素世界中的多世回溯是否真正好玩”。

## 1. 唯一验收目标

验证这条核心闭环：

```text
第一世不知道未来
→ 在像素世界中探索并做出选择
→ 因错误判断死亡
→ 获得 Knowledge
→ 死亡结算
→ 承世 / 悟世
→ 回到初始 Anchor
→ 利用前世信息改变地图行动与事件选择
→ 进入第一世无法到达的新未来
```

如果第二世只是“重新打一遍第一世”，V0.1 就不算成功。

## 2. V0.1 产品范围

### 必须实现

- Windows 桌面可运行构建。
- 固定主角沈川。
- 真实可移动的像素角色。
- 青玄宗、青石坊市、黑水山脉、黑水秘境最小地图。
- 地图切换 / Zone / 关键交互点。
- 5～8 个重要 NPC。
- 简单 NPC 出现位置 / 时间段状态。
- 游戏内时间。
- 修炼。
- 最小战斗。
- Event Engine。
- Condition / Choice / Effect。
- Knowledge。
- 死亡。
- 主动坐化。
- 一世评价。
- 承世。
- 悟世。
- 词条库与最多 5 个装备词条。
- 10 次基础回溯。
- 锚点命运 + 一世变数。
- 确定性重大结果。
- 本地 Save / Load。
- Scenario Test 可以无画面完整跑通黑水三世。

### 明确不作为验收条件

- 筑基以上完整成长。
- 大型开放世界。
- 完整宗门经营。
- 建造 / 制造 / 农业模拟。
- 复杂经济系统。
- 大量程序化地图。
- 多人联机。
- 账号系统。
- 真实支付。
- Steamworks / Achievement / Cloud 正式接入。
- Steam Deck / Linux / macOS 正式支持。
- 运行时 AI NPC Agent。
- 高成本 HD-2D 3D 场景。
- 动作 RPG 连招系统。

## 3. V0.1 地图范围

```text
青玄宗
├─ 外门区域
├─ 修炼点
├─ 丹阁入口
├─ 任务堂 / 山门关键入口
└─ 重要 NPC 交互点

青石坊市
├─ 商铺 / 摊位
├─ 丹药购买
└─ 情报 / NPC 事件点

黑水山脉
├─ 山道
├─ 危险区域
├─ 调查点
└─ 通往秘境入口

黑水秘境
├─ 第一层危险
├─ 第二层杀阵
└─ 第三世新路线
```

不追求地图面积，追求同一地点在三世中产生不同意义。

## 4. 固定角色

```text
姓名：沈川
年龄：16
境界：炼气三层
身份：青玄宗外门弟子
起始地点：青玄宗外门
基础回溯：10
```

初始 Anchor：

```text
ANCHOR_QI_REFINING_INITIAL
```

V0.1 只有这一真实可用 Anchor。

## 5. 第一世：不知道危险

目标：让玩家通过真实地图行为自然进入黑水事件，而不是从主菜单直接点“黑水剧情”。

建议路径：

```text
青玄宗修炼 / 接触人物
↓
从 NPC 或地点事件获得黑水线索
↓
前往青石坊市准备普通资源
↓
进入黑水山脉
↓
接触赵长青相关事件
↓
接受看似合理的灵酒 / 决策
↓
中毒
↓
死亡
```

死亡后获得：

```text
K_BLACKWATER_POISON
“赵长青提供的灵酒有毒。”
```

第一世重点验证：

- 地图移动与交互是否顺畅。
- 事件不是与地图割裂的弹窗。
- 死亡是否留下明确的信息价值。

## 6. 第二世：Knowledge 改变行动

回到初始 Anchor 后：

- 世界现实恢复。
- NPC 不认识未来的沈川。
- 玩家保留 `K_BLACKWATER_POISON`。

黑水相关交互应出现新可能：

```text
普通：饮下灵酒
★ 前世记忆：你知道酒有毒
```

Knowledge 不只改变对话，还应允许地图层面的提前行动：

- 在坊市提前买解毒丹。
- 先找丹阁 NPC 求证。
- 跟踪赵长青。
- 从另一条路径进入黑水区域。

玩家避开第一层毒杀后，进入第一世无法到达的第二层危险，并最终因杀阵 / 环境机制死亡。

获得：

```text
K_BLACKWATER_KILLING_ARRAY
“第二层入口存在杀阵，正面进入必死。”
```

## 7. 第三世：Knowledge + 词条 + 准备

第三世需要证明多个跨世系统可以组合。

玩家：

- 利用 `K_BLACKWATER_POISON` 避开毒杀。
- 利用 `K_BLACKWATER_KILLING_ARRAY` 提前准备。
- 装备第二世悟出的词条。
- 在青玄宗 / 坊市提前寻找破阵资源。
- 进入前两世不可达的新路线。

本世至少取得一个有价值实体成果：

- 功法。
- 装备。
- 丹药。
- 特殊玉简。
- 唯一物测试对象。

随后通过正常死亡或主动坐化验证承世。

## 8. 战斗 V0.1

战斗只需要证明：

- 地图能触发战斗。
- 玩家可以选择攻击 / 技能 / 物品 / 逃跑等少量行为。
- 功法、装备、词条和 Knowledge 能影响战斗前准备或战斗选项。
- 伤势 / 死亡能回到统一人生规则。

建议内容上限：

- 5 种以内敌人。
- 10 个以内战斗技能。
- 1 个精英 / 关键战斗。

不要求动作连招和高成本演出。

具体战斗制式在引擎选型时最终确认。

## 9. 悟世验证

V0.1 准备 5～8 个规则可判定词条，例如：

- 察危：危险交互出现额外风险提示。
- 识毒：毒物 / 药物出现额外信息或选项。
- 丹心：丹道相关事件获得额外理解。
- 剑感：剑道事件 / 技能获得额外选择。
- 苟命：逃生与撤退路线更丰富。

必须验证：

- 立即坐化不会稳定刷词条。
- 一世可以有 0～3 个候选。
- 候选来自真实人生事实。
- 同源升级替换旧阶。
- 每世最多装备 5 个。

## 10. 承世验证

至少准备：

- 一门可承世功法。
- 一件普通装备。
- 一种可堆叠丹药。
- 一个唯一物测试对象。

必须验证：

- 只从死亡时仍合法拥有的成果中选。
- 境界 / 修为绝不出现。
- 一次一个成果单位。
- 高阶物品仍受条件限制。
- 唯一物不能被回溯复制。

## 11. 地图重复体验验证

第二世开始后不能要求玩家完整机械重走第一世。

至少实现一种减少重复的机制：

- 已知安全地点快速旅行；或
- 已解决低风险交互快速处理；或
- 前世路线摘要 / 快捷行动。

但黑水关键准备、风险与分支仍必须由玩家主动决定。

## 12. 随机验证

### 锚点命运

相同 Anchor 下核心事实可复现。

### 一世变数

普通遭遇、天气、非核心事件允许变化。

### 防烧随机

必须测试：

```text
路径 A：直接进入重大事件
路径 B：先移动、绕路或执行若干无关动作再进入重大事件
```

只要关键状态与选择相同，重大结果不能因为移动步数、帧数或无关操作改变。

## 13. 本地存档验证

必须支持：

- 保存当前世界。
- 退出游戏。
- 再次启动。
- 恢复当前一世。
- 不错误触发死亡或回溯。

Save 需要记录：

- World。
- Anchor。
- CurrentLife。
- Knowledge。
- Traits。
- Inventory。
- NPC / World / Event State。
- rule/content/balance version。

## 14. AI / 自动化测试要求

V0.1 不能只靠人工玩一遍验收。

至少建立：

```text
L1 Core Unit Test
L2 Blackwater Three-Life Scenario Test
L3 Headless / Runtime Integration Test
L4 Visual / Input Smoke Test
```

最重要的是 L2：

> **在不启动正式画面的情况下，完整跑通第一世 → 第二世 → 第三世，并验证 Knowledge 改变合法行动与结果。**

## 15. 内容量上限

V0.1 建议控制：

- 4～5 个地图 / 区域。
- 5～8 个重要 NPC。
- 5 种以内敌人。
- 3～5 门功法。
- 10 个以内战斗技能。
- 20～30 个普通 / 地点事件。
- 10～15 个条件事件。
- 1 条完整黑水三世核心事件链。

达到验证目标以后再增加内容。

## 16. 完成标准

V0.1 完成至少满足：

1. Windows 桌面构建可独立启动。
2. 玩家可以实际控制角色探索四个最小区域。
3. 第一世能够自然走入黑水死亡。
4. 第一世 Knowledge 能改变第二世地图行动 / 事件选择。
5. 第二世改变结果后进入第一世不存在的新内容。
6. 第三世通过 Knowledge + 词条 + 提前准备打开新路线。
7. 悟世候选基于经历。
8. 承世能够带一项合法成果进入下一世。
9. 重大随机不能被移动、帧数或无关操作操纵。
10. Save / Load 不改变权威人生状态。
11. 黑水三世 Scenario Test 可以由 AI / CI 自动运行。

完成这些以后，才进入更大地图、多 Anchor、筑基阶段和 Steam 平台集成。
