# 诸世问道：V0.1 可玩原型

> 状态：当前有效开发基线
>
> V0.1 的目的不是完成完整修仙游戏，而是验证“可探索像素世界 + 多世回溯”是否真正好玩。

## 1. 唯一验收目标

验证这条核心闭环：

```text
第一世不知道未来
→ 在像素地图中探索 / 接触 NPC / 修炼
→ 因错误判断死亡
→ 获得 Knowledge
→ 死亡结算
→ 承世 / 悟世
→ 回到初始 Anchor
→ 重新走进同一世界
→ 利用前世信息做出不同选择
→ 改变事件结果
→ 进入新的未来内容
```

只要玩家没有明显感受到：

> **“我真的回到了过去，而且我知道上一世不知道的事情。”**

V0.1 就不算完成。

## 2. V0.1 产品形态

V0.1 是一个 **Windows 桌面像素 RPG 纵切**，不是 H5 / 小程序原型。

玩家必须可以直接控制角色：

- 在地图中移动。
- 进入地点。
- 与 NPC 交互。
- 调查场景。
- 修炼。
- 购买 / 使用少量物品。
- 探索黑水区域。
- 进入事件。
- 进行最小战斗或危险判定。
- 死亡并回溯。

地图负责提供空间和沉浸，核心内容仍由 Event Engine、Knowledge、NPC / 世界状态和多世系统驱动。

## 3. 必须实现

### 核心玩法

- 固定主角。
- 一个自动建立的初始 Anchor。
- 炼气三层 → 炼气四层。
- 游戏内时间。
- 修炼。
- 条件 / 随机 / 连锁事件。
- Condition / Choice / Effect。
- Knowledge。
- 死亡。
- 主动坐化。
- 一世评价。
- 承世。
- 悟世。
- 词条库。
- 最多 5 个装备词条。
- 词条升级的数据能力。
- 基础 10 次回溯。
- 锚点命运 + 一世变数。
- 确定性重大结果。

### 像素 RPG 表现

- 角色可移动。
- 地点之间存在真实地图连接。
- NPC 具有地图位置 / 可交互入口。
- 场景对象可以触发调查 / 事件。
- 事件界面与地图之间能自然切换。
- 角色状态、背包、功法、Knowledge、词条可查看。
- 死亡后可以完成完整轮回结算。

### 本地运行

- Windows 桌面可执行构建。
- 本地 SaveGame。
- 不依赖常驻服务端才能游玩。
- 核心规则可脱离画面测试。

## 4. 明确不作为验收条件

- 筑基、金丹、元婴完整成长。
- 多大境界 Anchor UI 与完整定世平衡。
- 大开放世界。
- 全世界 NPC 自主演化模拟。
- 宗门经营。
- 建造系统。
- 深度制造系统。
- 复杂经济模拟。
- 大量生活职业。
- 动作 RPG 连招。
- 大规模弹幕战斗。
- 数十张地图。
- 大量怪物和技能。
- HD-2D 精品 JRPG 级 3D 场景制作。
- Steamworks 正式集成。
- Steam 商店发布。
- 多人联机。
- 运行时 AI 权威规则。

## 5. 固定角色

```text
姓名：沈川
年龄：16
境界：炼气三层
身份：青玄宗外门弟子
起始地点：青玄宗外门
基础回溯：10
```

初始 Anchor：

```text
ANCHOR_QI_REFINING_INITIAL
```

V0.1 只有这一个真实可用 Anchor。

## 6. V0.1 地图范围

严格限制为：

```text
青玄宗        1 个主要区域
青石坊市      1 个主要区域
黑水山脉      1～2 张探索地图
黑水秘境      1 张核心地图
```

地图不追求大。

每张地图只需要支撑：

- 清晰移动路径。
- 关键 NPC。
- 少量调查点。
- 少量资源 / 商店 / 功能点。
- 事件触发位置。
- 进入下一地点的连接。

同一地点可以通过时间、NPC 状态、Knowledge 和事件链产生不同内容，不靠不断增加新地图制造内容量。

## 7. NPC 范围

V0.1 重要 NPC 控制在 **5～8 个**。

NPC 不需要完整 Agent 模拟。

每个重要 NPC 至少具有：

- 当前地点 / 出现条件。
- 关系状态。
- 关键标签。
- 一条秘密或动机。
- 专属事件入口。
- 与黑水主线的可能关系。

前世 Knowledge 应能改变玩家面对同一 NPC 时的可用信息和选项。

## 8. 黑水核心事件链

同一初始 Anchor 下保持稳定：

- 黑水相关事件会发生。
- 核心人物的关键动机有稳定根因。
- 第一层危险具有固定真实原因。
- 更深处存在第二层致命机制。
- Knowledge 能提前改变玩家处理方式。

普通遭遇、非关键 NPC 位置、资源细节等可以变化。

## 9. 建议三世体验

### 第一世：不知道危险

```text
青玄宗活动
↓
修炼 / 接触 NPC
↓
前往青石坊市或黑水山脉
↓
进入黑水相关事件
↓
接受看似合理的选择
↓
中毒 / 致命后果
↓
死亡
```

获得：

```text
K_BLACKWATER_POISON
“此处提供的酒有毒。”
```

### 第二世：利用 Knowledge

再次从青玄宗初始 Anchor 开始。

玩家可以：

- 更快处理已知前置流程。
- 提前准备解毒资源。
- 对相关 NPC 出现前世记忆提示。
- 避开第一世毒杀。
- 进入第一世没见过的更深区域。

然后因第二层杀阵 / 环境机制死亡。

获得：

```text
K_BLACKWATER_KILLING_ARRAY
“第二层入口存在杀阵，正面进入必死。”
```

### 第三世：Knowledge + 词条

玩家：

- 直接处理第一层毒杀。
- 针对杀阵准备资源或寻找 NPC。
- 使用词条得到额外危险提示 / 特殊选择。
- 进入新路线。
- 获得一个值得承世的实体成果。

例如：

```text
破阵玉简
避毒法器
特殊功法
```

## 10. 战斗范围

V0.1 最多：

- 5 种以内敌人。
- 10 个以内战斗技能。
- 少量关键战斗。

战斗目标不是展示动作系统，而是验证：

- 功法 / 装备 / 状态能影响风险。
- 战斗失败可以造成伤势或死亡。
- Knowledge / 准备可以改变某些战斗前条件。

战斗形式在最终引擎选型后确认。

## 11. 悟世验证

至少准备 5～8 个规则可判定词条模板。

示例：

- 察危。
- 识毒。
- 丹心。
- 剑感。
- 苟命。

必须验证：

- 立即坐化不会稳定刷词条。
- 一世可以有 0～3 个候选。
- 候选来自真实经历。
- 同源升级替换旧阶。
- 每世最多装备 5 个。

## 12. 承世验证

至少准备：

- 一门可承世功法。
- 一件普通装备。
- 一种可堆叠丹药。
- 一个唯一物测试对象。

验证：

- 只能从死亡时仍拥有的成果中选。
- 境界 / 修为不出现。
- 一次只带一个成果单位。
- 容器不能套娃。
- 普通物品可多世重复获得。
- 唯一物不能通过回溯复制。

## 13. 回溯验证

必须覆盖：

- 新世界基础回溯 = 10。
- 第一次成功回溯后 = 9。
- 主动坐化进入相同死亡结算。
- 退出游戏 / 重新打开存档不等于死亡。
- 剩余为 0 时当前角色仍能继续玩到死亡。
- 0 次后死亡如何继续，V0.1 可以先使用明确的 DEV / 测试规则，不接账号付费系统。

旧“账号级付费回溯额度”不再属于当前 V0.1 验收基线。

## 14. 随机验证

### 锚点命运

相同 Anchor 下，关键事实必须可复现。

### 一世变数

不同 Life 可以出现不同普通遭遇。

### 防烧随机

必须保证：

```text
路径 A：直接进入重大事件
路径 B：先在地图走动 / 调查 / 做无关行动再进入重大事件
```

只要关键人物状态、关键世界状态和选择相同，重大结果不能因为：

- 多走了几步。
- 多渲染了几帧。
- 多打开了几次菜单。
- 多进行无关调查。

而发生变化。

## 15. AI 自动测试基线

V0.1 必须能通过自动化跑核心玩法，不允许只有人工游玩才能验证。

测试层次：

```text
L1 Core Unit Test
↓
L2 Blackwater Three-Life Scenario Test
↓
L3 Headless / Integration Test
↓
L4 Window + Input + Visual Smoke
```

核心 Scenario Test 必须能够在不依赖手工操作角色的情况下完整跑通：

```text
第一世死亡
→ Knowledge
→ 第二世新选项
→ 第二世死亡
→ 新 Knowledge / 悟世
→ 第三世新路线
→ 承世
```

## 16. 完成标准

V0.1 完成必须满足：

1. Windows 桌面版本可以实际运行。
2. 玩家能在像素地图中移动并完成核心地点交互。
3. 完整跑通至少三世黑水路线。
4. 第一世获得的 Knowledge 能改变第二世可选项。
5. 第二世改变结果后能进入第一世看不到的新内容。
6. 悟世候选基于经历，不是纯随机。
7. 承世能把一项合法成果带入下一世。
8. 境界与修为绝不承世。
9. 10 次基础回溯正确消耗。
10. 重大随机无法通过无关移动 / 输入 / 帧数操纵。
11. 核心规则可以无 UI 自动测试。
12. AI / Codex 可以通过 CLI 完成构建、运行测试、读取失败结果和再次回归。

完成这些以后，才讨论扩充地图、境界、Steamworks、Steam Deck 或正式发布。
