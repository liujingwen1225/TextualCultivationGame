# 诸世问道：V0.1 可玩原型

> 状态：当前有效开发基线
>
> V0.1 的目的不是完成完整修仙游戏，而是验证“死亡轮回是否真正好玩”。

## 1. 唯一验收目标

验证这条核心闭环：

```text
第一世不知道未来
→ 因错误判断死亡
→ 获得 Knowledge
→ 死亡结算
→ 承世 / 悟世
→ 回到初始 Anchor
→ 利用前世信息做出不同选择
→ 改变事件结果
→ 进入新的未来内容
```

只要这条链没有形成明显的“前世经验改变今生”的体验，V0.1 就不算完成。

## 2. V0.1 范围

### 必须实现

- 固定主角。
- 固定一个世界片段。
- 一个自动建立的初始 Anchor。
- 炼气三层 → 炼气四层。
- 游戏内时间。
- 修炼。
- 事件引擎。
- 条件 / 选择 / Effect。
- Knowledge。
- 死亡。
- 主动坐化。
- 一世评价。
- 承世。
- 悟世。
- 词条库。
- 最多 5 个装备词条。
- 词条升级的数据能力。
- 基础 10 次回溯。
- DEV 方式补充付费回溯额度。
- 锚点命运 + 一世变数。
- 确定性重大结果。
- 一个 Web/H5 可玩客户端。

### 明确不做为验收条件

- 筑基、金丹、元婴完整成长。
- 多大境界 Anchor UI 与完整定世流程。
- 多世界模板组合。
- 真实充值支付。
- 微信登录。
- 手机号短信登录。
- 微信小程序正式发布。
- App 打包。
- Tauri 桌面端。
- 运行时 AI 生成人生评价。
- 大规模 NPC Agent。
- 完整宗门经营。

后续系统的数据结构可以为这些能力留扩展点，但 V0.1 不为未来功能提前实现复杂基础设施。

## 3. 固定角色

示例：

```text
姓名：沈川
年龄：16
境界：炼气三层
身份：青玄宗外门弟子
起始地点：青玄宗外门
基础回溯：10
```

初始 Anchor 自动建立：

```text
ANCHOR_QI_REFINING_INITIAL
```

V0.1 只有这一个真实可用 Anchor。

## 4. 黑水核心事件链

V0.1 使用“黑水”作为固定验证场景。

### 核心锚点命运

同一初始 Anchor 下稳定：

- 黑水相关事件会发生。
- 某核心人物存在明确动机。
- 第一层危险具有固定真实原因。
- 更深处存在第二层致命机制。
- 玩家可以通过前世 Knowledge 提前改变处理方式。

普通支线和小遭遇允许变化。

## 5. 建议三世体验

### 第一世：不知道危险

```text
正常修炼 / 接触人物
↓
进入黑水相关事件
↓
接受看似合理的选择
↓
中毒 / 致命后果
↓
死亡
```

死亡后获得 Knowledge，例如：

```text
K_BLACKWATER_POISON
“此处提供的酒有毒。”
```

死亡结算展示：

- 一世摘要。
- 死亡原因。
- 本世 Knowledge。
- 承世候选（如果有）。
- 悟世候选（若人生轨迹达到条件）。

第一世可以没有强词条，避免让“死亡本身”自动产生奖励。

### 第二世：利用 Knowledge 改变第一层结果

回到初始 Anchor。

同一事件出现：

```text
普通选项：饮下灵酒
★ 前世记忆：你知道酒中有毒
```

选择前世记忆路线后：

- 避开第一次死亡。
- 触发新的后续事件。
- 进入黑水更深处。
- 遇到阵法或环境机制。
- 因缺乏进一步知识再次死亡。

获得第二条 Knowledge：

```text
K_BLACKWATER_KILLING_ARRAY
“第二层入口存在杀阵，正面进入必死。”
```

如果这一世形成鲜明轨迹，可以测试悟世候选，例如：

```text
【察危】
在危险事件中获得额外异常提示。
```

### 第三世：Knowledge + 词条改变路线

回到初始 Anchor，装备已获得词条。

玩家：

- 直接绕过已知毒杀。
- 对杀阵出现额外准备选择。
- 提前购买或寻找破阵资源。
- 进入此前不可到达的新内容。

本世可以获得一个有价值的实体成果，例如：

```text
破阵玉简
避毒法器
特殊功法
```

随后通过正常死亡或主动坐化测试“承世”。

下一世确认：

- 选择承世成果后能带回初始 Anchor。
- 境界与修为没有被带回。
- 高阶物品仍受使用条件限制。

## 6. 悟世验证

V0.1 至少准备 5～8 个可规则判定的词条模板，用于验证而不是追求内容量。

示例方向：

- 察危：危险事件提示能力。
- 识毒：毒物相关额外信息。
- 丹心：丹道事件额外选项。
- 剑感：剑道事件理解提升。
- 苟命：逃生相关额外选择。

必须验证：

- 立即坐化不会稳定刷出词条。
- 一世可以有 0～3 个候选。
- 候选来自真实行为标签。
- 同源升级替换旧阶。
- 每世最多装备 5 个。

## 7. 承世验证

至少准备：

- 一门可承世功法。
- 一件普通装备。
- 一种可堆叠丹药。
- 一个唯一物测试对象。

验证：

- 只能从死亡时仍拥有的成果中选。
- 境界 / 修为不出现。
- 一次只带一个成果单位。
- 容器不能套娃。
- 普通物品可多世重复获得。
- 唯一物一旦跨世取得，原获取路径不再产生第二份。

## 8. 回溯验证

必须覆盖：

- 新世界基础回溯 = 10。
- 第一次死亡后 = 9。
- 主动坐化同样消耗。
- 断线 / 退出客户端不消耗，也不结束当前一世。
- 剩余为 0 时当前角色仍能继续玩。
- 下一次死亡进入“补充额度 / 新世界”状态。
- DEV 增加账号付费回溯后可继续。

## 9. 随机验证

### 锚点命运

相同 Anchor 下，关键事实必须可复现。

### 一世变数

不同 Run 可以出现不同普通遭遇。

### 防烧随机

必须测试：

```text
路径 A：直接进入重大事件
路径 B：先做多次无关操作再进入重大事件
```

如果关键人物状态与选择相同，重大结果不能因为无关点击不同而改变。

## 10. 节奏验证

不以真实小时作为硬验收。

观察：

- 玩家是否连续大量点击修炼而无事发生。
- 2～4 个重大行动后是否通常有新变化。
- 重复第二世时是否明显比第一世更快理解和处理内容。
- 前世选项是否真的节省无意义重复。

## 11. V0.1 服务端最低能力

```text
POST /game/new-world
GET  /game/state
POST /game/action
GET  /game/current-event
POST /game/event/{id}/choice
POST /game/suicide
GET  /game/death-summary
POST /game/death/select-anchor
POST /game/death/inherit
POST /game/death/realize-trait
POST /game/next-life
GET  /game/knowledge
GET  /game/traits
POST /game/traits/loadout
```

接口名可以在实现时调整，但业务能力不能缺失。

## 12. 完成标准

V0.1 完成必须满足：

1. 完整跑通至少三世黑水路线。
2. 第一世获得的 Knowledge 能改变第二世可选项。
3. 第二世改变结果后能进入第一世看不到的新内容。
4. 悟世候选基于经历，不是纯随机。
5. 承世能把一项合法成果带入下一世。
6. 境界与修为绝不承世。
7. 10 次回溯正确消耗。
8. 主动坐化正确进入死亡结算。
9. 重大随机无法通过无关操作操纵。
10. 所有核心规则服务端权威。

完成这些以后，才进入 V0.2 的多 Anchor / 筑基阶段扩展。
