# V0.1 连续人生纵切

## 1. 唯一验收目标

V0.1 不验证多世回溯，也不验证完整境界体系。

它只回答一个问题：

> **“作为一个炼气期修士，在这个世界里探索、修炼、调查、准备、战斗并承担后果，本身是否好玩？”**

V0.1 必须像正式游戏的一个小片段，而不是临时 Demo 规则集合。

## 2. 纵切主题

固定主角：

```text
姓名：沈川
年龄：16
身份：青玄宗外门弟子
境界：炼气三层
```

连续体验：

```text
青玄宗外门
↓
日常修炼 / 人物接触
↓
发现黑水机会
↓
调查情报
↓
青石坊市准备
↓
黑水山探索
↓
RTwP 战斗
↓
黑水秘境
↓
揭开一层隐藏真相
↓
取得成果
↓
返回宗门
↓
人物 / 资源 / 世界状态持续改变
↓
继续自由行动一小段时间
↓
看到黑水事件产生的新关系、新机会或新限制
```

整个 V0.1 是一段连续人生，不要求玩家按脚本死亡。

## 3. 体验时长与内容预算

V0.1 是纵切，不追求商业 Demo 的内容时长。

目标首次完整游玩约：

> **45～75 分钟。**

内容预算原则：

- 1 条主机会：黑水事件。
- 3 个核心 NPC，最多再增加 2 个功能型 NPC。
- 4 类小型语义区域，不扩大成 4 张大地图。
- 1 条主要调查链。
- 最多 2 个必经战斗，允许 1 个可选战斗。
- 主角 4～6 个正式战斗能力。
- 1 个真正有代价的修炼选择。
- 1 个能够体现宗门身份的制度约束。
- 2～3 种明显结果路径。
- 5～10 分钟可玩的事件余波阶段。

若新增内容不能提高核心体验验证价值，应优先不做。

## 4. 地图范围

```text
青玄宗
├─ 外门生活区
├─ 修炼点
├─ 丹阁 / 资源服务点
└─ 关键 NPC 交互点

青石坊市
├─ 常规商铺 / 摊位
├─ 丹药 / 符箓 / 装备购买
└─ 情报 / 人物事件点

黑水山
├─ 山道
├─ 危险区域
├─ 调查点
└─ 秘境入口

黑水秘境
├─ 外围危险
├─ 核心战斗 / 阵法区域
└─ 隐藏真相与成果点
```

不追求面积，追求每个地点都有清晰玩法意义。

## 5. NPC 范围

3 个真正重要 NPC 为基线，最多扩展到 5 个有内容价值的 NPC。

至少包括：

- 一名与黑水事件直接相关的同门，例如赵长青。
- 一名宗门资源 / 丹药相关人物。
- 一名能够提供不同利益立场的人物。
- 可选：坊市商人 / 情报人物。

重要 NPC 至少验证：

- 时间段位置变化。
- 目标与当前状态。
- 基础关系变化。
- 不同情报 / 身份下的对话与行动差异。
- 玩家错过时间窗口后 NPC 会继续行动。

V0.1 不需要通用 NPC AI，也不需要让所有路人拥有完整 Schedule。

## 6. 黑水事件结构

黑水事件不再采用“第一世毒死、第二世阵死、第三世破局”的强制多世结构。

改为一条可调查、可失败、可绕行、可准备的事件链。

示意：

```text
表面：
赵长青邀沈川参与黑水相关机会，并出现一批看似正常的灵酒 / 丹药 / 资源。

调查层：
玩家可以直接接受，也可以检查来源、询问丹阁、跟踪人物、在坊市寻找替代资源。

隐藏层：
某批资源存在人为问题，背后涉及外门弟子、丹阁或某个利益关系。

秘境层：
即使避开前期风险，黑水内部仍有独立的阵法、环境和敌人问题。
```

V0.1 只需要揭开一层可信的隐藏真相，不需要搭建完整宗门阴谋。

## 7. 时间与机会

至少存在一个明确时间窗口，例如：

- 黑水秘境若干日后开放。
- 某 NPC 某日离开宗门。
- 某商人只在特定时间出现。

玩家修炼、疗伤、旅行都会消耗时间，因此无法完成所有准备。

时间压力必须来自有意义行为，而不是玩家在地图上多走几步或打开菜单。

## 8. 修炼验证

V0.1 不实现完整筑基，但修炼不能只是“消耗若干天 → 修为固定增加”。

必须至少存在一个真正有代价的修炼选择，例如：

```text
黑水开放还剩 5 天

闭关 3 天
→ 修为明显增加
→ 战斗状态更好
→ 调查时间减少

参悟术法 2 天
→ 修为增长较少
→ 获得或强化一个正式战术能力

暂不修炼
→ 腾出时间调查、交易或处理人物关系
```

具体数值后续平衡，但必须验证：

- 修炼消耗世界时间。
- 修炼与调查 / 交易 / 社交争夺同一时间资源。
- 不同修炼选择能够改变后续合法方案或战斗准备。
- 玩家能感受到“修炼是人生安排”，而不是独立经验按钮。

沈川固定炼气三层开局，不实现完整筑基。

可以通过 NPC、情报或场景展示筑基修士与筑基资源，让世界显得比 V0.1 更大。

## 9. 宗门身份验证

青玄宗不能只是地图背景或新手村。

V0.1 至少验证一条真实制度约束，让玩家感受到“外门弟子”身份同时带来资源与义务。

可以采用一条即可，例如：

- 外门弟子可领取一次宗门份额，但部分资源不能自由出售。
- 黑水所得中的某类物品原则上需要上报宗门。
- 某区域 / 设施只有特定身份可进入。
- 某宗门事务会占用时间，否则影响人物或资源关系。

不需要因此实现完整宗门派系政治、功勋体系或宗门经营。

验证目标是：

> **身份真正改变玩家可以做什么、获得什么以及需要承担什么。**

## 10. 资源取舍

必须验证“知道问题不等于买得起所有答案”。

例如：

```text
沈川可用灵石：120

解毒丹：45
破阵符：70
疗伤丹：30
更好武器：90
```

玩家不能一次买齐全部准备，需要根据情报做选择。

数值仅为示意，后续平衡。

## 11. 战斗验证

直接使用正式目标制式：

```text
当前地图 Combat State
+ RTwP
+ 暂停下令
+ 位置 / 距离
+ 动作时间
+ 术法
+ 法宝 / 消耗品
+ 伤势
+ 逃跑
```

内容上限：

- 3 种左右普通敌人。
- 1 个关键精英 / 修士战。
- 4～6 个主角战斗能力。
- 1～2 件有主动意义的法宝 / 装备。
- 少量丹药 / 符箓。

不做盟友复杂微操。

V0.1 不需要复杂连续物理、完整视线系统或大型导航战术模拟，只实现支撑当前战斗所需的正式规则子集。

## 12. 情报验证

至少验证：

- 从 NPC、调查点或事件中获得情报。
- 情报改变后续对话、准备或战斗选择。
- 至少有一条“传闻 / 推断 / 验证”的信息演进。
- 情报不会自动公布完整答案。

示例：

```text
观察：喝下某批灵酒后出现异常症状
↓
调查：灵酒来自特定来源
↓
验证：发现其中确有异常材料
↓
行动：换药、避开、调包、拿证据交换利益
```

## 13. 后果与事件余波

V0.1 结束时必须能看到持续后果，而不是副本结算后世界复原：

- NPC 关系变化。
- 某角色是否受伤 / 离开 / 获益。
- 黑水事件状态变化。
- 玩家资源与伤势保留。
- 获得的功法 / 物品 / 情报继续存在。
- 返回宗门后开放新的对话、机会或限制。

黑水事件结束后不能立即弹出“V0.1 完成”。

至少保留 5～10 分钟可自由行动的事件余波阶段，例如：

```text
返回青玄宗
↓
重新自由行动
↓
某 NPC 态度或位置发生变化
↓
某宗门资源 / 身份 / 情报发生变化
↓
出现一个由黑水结果产生的新机会或新限制
↓
V0.1 结束
```

这一段的目标不是增加新剧情，而是证明：

> **事件会改变人生，世界不会在一次冒险后复原。**

## 14. Save / Load

使用普通单机 SaveGame：

- 手动保存。
- 关键节点自动保存。
- 退出并重新启动后恢复。
- 死亡后读取最近合法存档 / 检查点。

Save/Load 不触发任何多世、Anchor、Knowledge Meta 或继承规则。

## 15. 自动化测试

至少建立：

```text
L0 Build / Content Validation
L1 Pure C# Game Core Unit Tests
L2 Blackwater Continuous-Life Scenario Test
L3 Godot Headless Runtime Integration
L4 Visual / Input Smoke Test
```

L2 不启动正式画面，也能执行：

```text
开局
→ 获取机会
→ 调查
→ 修炼 / 购买准备
→ 进入黑水
→ 战斗 / 事件
→ 返回宗门
→ 继续余波阶段
→ 验证世界与 NPC 后果
```

详细测试边界见 `13-test-architecture.md`。

## 16. 两类验收门

V0.1 完成必须同时通过两类不同验收，不能混成一个“所有测试都绿”的结论。

### 16.1 Player Experience Gate

验证游戏本身是否成立：

- 连续修仙人生体验成立。
- 修炼选择有代价。
- 调查和情报改变行动。
- 时间形成机会成本。
- 资源存在真实取舍。
- 宗门身份产生制度意义。
- NPC 会继续行动。
- RTwP 战斗有准备与战术价值。
- 伤势和资源后果持续存在。
- 黑水结束后的余波能够被玩家继续体验。

### 16.2 Technical Confidence Gate

验证工程基础是否可靠：

- Windows 构建可启动。
- Save / Load 正确恢复权威状态。
- Core Tests 通过。
- Scenario Test 可重复运行。
- Godot Headless 集成通过。
- 基础 Visual / Input Smoke 可执行。

技术测试全绿不能替代玩法体验验收。

## 17. 明确不做

V0.1 不实现：

- Anchor / 回溯 / 承世 / 悟世 / 跨世 Trait。
- 筑基完整突破与第二大境界规则层。
- 完整宗门派系政治。
- 家族路线。
- 大规模经济模拟。
- 世界程序化生成。
- 大型开放世界。
- Steamworks 正式集成。
- 运行时 AI NPC Agent。
- 复杂生产系统。
- 通用 NPC AI 框架。
- 完整社会模拟。
- 复杂连续物理 / 全功能战术导航系统。

## 18. 完成标准

V0.1 完成至少满足：

1. Windows 构建可启动。
2. 玩家可控制沈川探索四类最小区域。
3. 游戏时间能够被修炼、旅行、疗伤等有意义行为推进。
4. 至少存在一个有真实机会成本的修炼选择。
5. 至少一条宗门制度规则会改变玩家的资源、权限或义务。
6. NPC 会基于时间和状态改变位置 / 行为。
7. 情报能改变准备、对话或战斗合法选项。
8. 玩家面对真实资源取舍。
9. RTwP 战斗能够完整跑通。
10. 伤势和资源后果会延续到战斗后。
11. 黑水事件至少有一层可调查隐藏真相。
12. 事件结束后 NPC / 世界状态持续改变。
13. 返回宗门后存在可玩的事件余波，并产生至少一个新机会或新限制。
14. 普通 Save / Load 能正确恢复权威状态。
15. Continuous-Life Scenario Test 可在 CI / AI 环境自动运行。
16. Player Experience Gate 与 Technical Confidence Gate 分别完成验收。
