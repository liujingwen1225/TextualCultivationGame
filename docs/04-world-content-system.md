# 诸世问道：世界、NPC 与内容系统

> 状态：当前有效基线

## 1. 设计目标

世界不是持续自主模拟的“大沙盘”，而是服务玩家人生与事件链的 **可组合内容世界**。

设计重点：

- 世界要有稳定骨架，才能让 Knowledge 有价值。
- 同一 Anchor 下要有变化，避免纯背答案。
- 真正新世界要改变地图、人物和核心真相，避免账号层面的攻略永久破解所有世界。
- 内容必须能够被一个人长期维护和扩展。

## 2. 世界结构

推荐层级：

```text
World
├─ Region
│  ├─ Location
│  │  ├─ SubLocation
│  │  └─ Event Pool
│  └─ Faction / Sect
├─ NPC Group
├─ Secret Realm
├─ Event Chain Pack
└─ World Crisis Pack
```

不要求实时模拟所有地点与 NPC。

只有与当前玩家状态、时间和事件相关的部分进入活跃计算。

## 3. 世界模板与预设模块组合

正式游戏不使用 AI 或程序运行时从零生成整个世界。

内容由开发者预设模块组成：

- 地图区域包。
- 宗门 / 势力包。
- NPC 人物组。
- 秘境包。
- 事件链包。
- 世界危机包。
- 资源分布包。

新世界根据兼容规则组合。

例如：

```text
东荒区域包
+ 青玄宗势力包
+ NPC组C
+ 黑水秘境包
+ 魔宗渗透事件链
```

## 4. 新世界必须改变核心答案

真正的新世界不能只是改名字。

允许变化：

- 地图布局。
- 宗门与势力。
- NPC 组合。
- 谁是敌人或内鬼。
- 危险来源。
- 秘境机制。
- 关键事件真相。
- 重要传承位置与获得方法。

例如：

```text
世界 A：某 NPC 下毒
世界 B：另一个 NPC 布阵
世界 C：不存在该阴谋，而是妖兽灾害
```

这样新世界清空 Knowledge 才有实际意义。

## 5. NPC 系统

NPC 不需要全部由 AI Agent 驱动。

推荐分层：

### S 级核心人物

- 长期人物线。
- 多层秘密。
- 多种关系维度。
- 可参与重大事件链。

### A 级重要人物

- 有清晰动机和事件线。
- 能对玩家路线产生影响。

### B 级模板人物

- 服务宗门任务、市场、普通事件与世界氛围。
- 允许基于模板生成具体实例。

## 6. NPC 关系

关系不只使用一个“好感度”。

按需要使用：

- 亲近 / 好感。
- 信任。
- 尊敬 / 畏惧。
- 怀疑。
- 兴趣。
- 敌意。

不是所有 NPC 都必须拥有全部维度。

关系属于 Anchor / 当前人生世界状态，不是 Knowledge，也不是跨新世界 Meta。

## 7. NPC 记忆与玩家 Knowledge

必须区分：

### NPC 记忆

属于某个 Anchor 之后的世界状态。

回到更早 Anchor 时，NPC 不会记得尚未发生的未来。

### 玩家 Knowledge

属于当前世界 Meta。

玩家仍然记得前世发生过什么，因此可以出现：

```text
★ 前世记忆：你知道此人会在三年后背叛宗门
```

这正是玩家与 NPC 信息不对称的核心乐趣。

## 8. NPC 秘密

秘密可以具有认知状态：

- Unknown。
- Suspected。
- Confirmed。
- Public。

秘密被玩家确认后，可以形成 Knowledge。

如果世界线变化导致秘密不再适用，Knowledge 不删除，而改变适用性。

## 9. 宗门与势力

宗门主要作为事件和权限网络，而不是经营模拟。

核心状态：

- 身份。
- 职位 / 阶层。
- 贡献。
- 权限。
- 派系关系。
- 师承。
- 核心人物关系。

宗门行为事件化：

- 接任务。
- 争夺资源。
- 晋升。
- 师门事件。
- 派系冲突。
- 宗门危机。

## 10. 秘境

秘境是高密度事件网络，不是简单副本列表。

典型结构：

```text
进入
↓
路线选择
↓
资源 / Knowledge / 危险
↓
是否继续深入
↓
更高收益 + 更高死亡风险
↓
撤离 / 死亡 / 获得核心成果
```

承世机制使秘境选择更重要：

> 拿到好东西并不等于永久拥有；玩家还要考虑能否活到死亡结算、承世选择，以及是否能将其带入新的 Anchor。

## 11. 事件内容模型

基础事件建议包含：

```text
Event
├─ id
├─ title / text
├─ tags
├─ conditions
├─ choices
│  ├─ conditions
│  ├─ effects
│  └─ next
├─ knowledgeRewards
├─ chainId
├─ priority
└─ cooldown / repeatPolicy
```

### Condition

支持组合：

- all。
- any。
- not。

典型条件：

- 境界。
- 地点。
- 时间。
- NPC 状态。
- 关系。
- Knowledge。
- 已装备词条。
- 持有物品。
- 已发生事件。
- 世界模板标签。

### Effect

典型效果：

- 时间推进。
- 修为与状态。
- 资源变化。
- NPC 关系变化。
- 物品获得 / 消耗。
- 伤势。
- Knowledge 获得。
- 事件链推进。
- 世界状态变化。
- 死亡。

## 12. 事件链

事件链用于表达持续因果：

```text
发现异状
→ 调查
→ 获得线索
→ 选择是否干预
→ 人物反应
→ 新结果
```

事件链状态属于当前人生 / Anchor 派生状态。

玩家回到更早 Anchor 后，事件链世界状态可以重置，但玩家 Knowledge 保留。

## 13. 熟悉状态

地点、事件和人物的“熟悉”不作为单独核心资源。

它可以由：

- Knowledge。
- 已经历次数。
- 已解决路径。

派生。

用途：

- 快速处理重复内容。
- 显示摘要而不是完整文本。
- 解锁已知路线。
- 降低无意义重复操作。

## 14. 内容生产规则

优先生产能支持多世玩法的内容：

### 高价值内容

- 第一次不知道会吃亏。
- 第二次有 Knowledge 可以改变。
- 第三次因为前面改变又产生新情况。

### 低价值内容

- 每次都完全一样。
- 无论选什么结果都一样。
- 只提供数值，没有信息。
- 死亡后没有任何可学习内容。

## 15. AI 使用边界

AI 可以帮助：

- 根据规则事实生成人生评价文案。
- 为同一事件生成不同语气文本。
- 帮助开发者批量起草事件。
- 辅助检查内容重复。

但内容进入游戏前必须编译成确定规则。

运行时 AI 不得直接创建：

- 未验证的奖励。
- 任意 Condition / Effect。
- 随机改变世界核心真相。
- 绕过唯一物和 Anchor 规则的结果。

## 16. V0.1 世界范围

V0.1 不做模块组合。

只提供一个固定世界片段：

- 青玄宗背景。
- 黑水山 / 黑水秘境。
- 少量核心 NPC。
- 一条三世可验证的核心事件链。
- 若干普通支线用于验证一世变数。

模块化结构在数据模型层保留，但不作为 V0.1 内容量目标。
