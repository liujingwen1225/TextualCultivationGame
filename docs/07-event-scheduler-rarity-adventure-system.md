# 诸世问道：事件调度、稀有度与奇遇系统

> 状态：设计基线 V0.1  
> 依赖：`01-game-system-framework.md`、`03-event-content-specification.md`、`05-time-simulation-rewind-system.md`、`06-random-event-system.md`  
> 目标：定义事件如何进入候选池、如何抽取、如何避免重复、如何形成奇遇与长事件链，以及前世知识和世界线偏移如何改变事件分布。

---

# 1. 核心目标

长期游玩主要依靠“经历不同”，而不是依靠“升级极慢”。

事件系统必须实现以下体验：

1. 同一个境界、同一个地点、同一种行动，不保证每一世看到完全相同的内容。
2. 关键剧情仍然可控，不允许因为随机性导致玩家永久错过核心玩法。
3. 随机事件必须与当前角色状态、地点、NPC、时间、世界状态相关，而不是无意义抽卡。
4. 小事件可以自然演化成长事件链。
5. 前世知识不仅解锁选项，也可以改变事件池和事件权重。
6. 玩家改变世界后，旧事件会消失、新事件会进入池中，形成“世界线偏移”。
7. 稀有事件应让玩家产生“这一世居然遇到了这个”的惊喜，但不能成为毕业所需的纯 RNG 门槛。

设计原则：

> 随机负责制造经历差异，规则负责保证游戏公平，事件链负责制造意义。

# 2. 事件调度总流程

每次玩家完成会推进时间的行动后，统一执行事件调度。

```text
玩家行动完成
    ↓
时间推进
    ↓
处理强制事件
    ↓
处理已预约事件
    ↓
判断是否进入随机事件检查
    ↓
建立候选事件池
    ↓
条件过滤
    ↓
事件权重修正
    ↓
重复衰减 / 冷却
    ↓
保护与保底修正
    ↓
抽取事件
    ↓
进入事件选择
    ↓
结算 Effect
    ↓
更新 Event State / NPC / Knowledge / World State
```

重要：一次行动不应该连续弹出大量互不相关事件。

V0.1 默认：

- 普通行动结束最多触发 1 个主要交互事件。
- 强制世界事件可以覆盖普通随机事件。
- 部分仅提供信息的“小通知”可以与主要事件并存，但不要求玩家连续做选择。

---

# 3. 事件触发层级

事件按照调度优先级分为 6 层。

## P0：立即强制事件

必须立即处理，不可被随机事件覆盖。

例如：

- 玩家死亡
- 突破失控
- 秘境坍塌
- 当前地点遭到袭击
- 剧毒发作

## P1：时间节点事件

达到确定日期或时间窗口后触发。

例如：

- 宗门大比
- 黑水秘境开启
- 月度俸禄
- 某 NPC 约定会面

## P2：事件链继续节点

玩家已经进入某个 Chain 后，其后继节点拥有较高优先级。

例如：

```text
夜闻异响
↓
发现黑衣人
↓
三日后再次遇见
```

如果后继节点条件已经满足，不应该长期被普通随机事件挤掉。

## P3：条件剧情事件

满足特定条件后进入候选池。

例如：

- 与陆清瑶信任达到 40
- 拥有古修残卷
- 学会基础阵解

## P4：普通随机事件

构成日常内容密度的主体。

## P5：环境氛围事件

低影响、小文本，用于世界生活感。

例如：

- 宗门下雪
- 坊市出现外地商队
- 某峰长老公开讲法

P5 可以没有复杂分支，也不计入主要事件冷却。

---

# 4. 事件候选池

每次调度不从全游戏事件中抽取，而是动态构建候选池。

候选池至少由以下维度组成：

```text
当前地点池
+
当前境界池
+
当前行动池
+
NPC关系池
+
当前世界主题池
+
事件链池
+
前世知识池
+
特殊状态池
```

例如玩家在青玄宗闭关：

```text
青玄宗事件
+
修炼类事件
+
当前功法事件
+
师门 NPC 事件
+
经脉/瓶颈事件
+
本世活跃主题
```

不会抽到：

> “在黑水山脉遭遇妖兽”。

---

# 5. 基础触发率不是固定百分比

不建议设计成：

> 每修炼一次 20% 出事件。

这样容易被玩家机械刷行动。

推荐使用“事件压力 Event Pressure”。

## 5.1 Event Pressure

每个 Run 保存：

```text
eventPressure: 0 ~ 100
```

执行普通行动后逐渐增加。

示意：

| 行动 | 压力增加 |
|---|---:|
| 修炼 3 天 | +12 |
| 坊市移动 | +8 |
| 宗门任务 | +18 |
| 闭关 30 天 | +30 |
| 秘境探索 | 由节点直接控制 |

当压力越高，越容易触发随机事件。

事件触发后：

```text
eventPressure -= eventCost
```

例如普通事件消耗 35，重要事件消耗 60。

目的：

- 防止连续很久什么都不发生。
- 防止连续刷出大量事件。
- 允许不同操作拥有不同内容密度。

具体参数必须由试玩调节，不作为最终常量。

---

# 6. 权重模型

每个事件有基础权重：

```text
baseWeight
```

实际权重建议：

```text
finalWeight =
baseWeight
× locationModifier
× actionModifier
× stateModifier
× themeModifier
× relationshipModifier
× knowledgeModifier
× repetitionModifier
× rarityModifier
× worldlineModifier
```

不要求第一版所有 Modifier 都复杂实现，但数据结构应可扩展。

# 7. 事件稀有度

稀有度描述“出现频率”，而不是单纯描述奖励强度。

建议五档：

| 稀有度 | 名称 | 定位 |
|---|---|---|
| C | 常见 | 修仙日常、资源、小关系变化 |
| U | 少见 | 条件较具体、有明显选择价值 |
| R | 稀有 | 特殊人物、罕见资源、隐藏线索 |
| E | 奇遇 | 足以改变当前一世路线 |
| L | 天命 | 极少见、跨世有意义的重大事件 |

正式 UI 不一定显示英文字母，可展示为：普通 / 少见 / 稀有 / 奇遇 / 天命。

## 7.1 稀有不等于强

例如：

> “捡到元婴传承”

不能因为是天命事件就让炼气玩家无条件毕业。

稀有事件更适合提供：

- 特殊路线入口
- 强烈风险收益选择
- 世界秘密
- 特殊 NPC
- 特殊功法线索
- 后续长事件链

而不是直接给大量属性。

# 8. 奇遇机制

奇遇不是普通随机事件换一个金色边框。

一次合格奇遇至少满足两项：

1. 明显改变当前 Run 的计划。
2. 开启普通流程无法直接获得的新路线。
3. 引入新的 NPC / 地点 / 秘密。
4. 带来高风险高收益决策。
5. 产生可以跨世继承的 Knowledge。
6. 形成后续 Chain。

示例：

```text
你在后山采药时发现一名奄奄一息的散修。

① 救治他
② 搜走储物袋离开
③ 通知宗门执事
④ 暗中观察
```

不同结果可能分别进入：

```text
古修传承线
黑市追杀线
宗门功勋线
魔宗暗线
```

因此奇遇是“路线生成器”，不是奖励箱。

---

# 9. 奇遇保护规则

奇遇可以稀有，但不能完全靠无限抽奖。

推荐：

## 9.1 软保底

长时间未遇到 R/E/L 事件时，提高高稀有事件的候选权重。

但只在：

- 当前区域确实存在合适事件
- 满足基本条件

时生效。

不能凭空生成不符合世界状态的奇遇。

## 9.2 路线保底

如果玩家已经通过多个线索接近某一事件链入口，则入口事件应逐渐从“随机”变成“高概率/条件触发”。

例如：

```text
获得残破地图
+
听到散修传闻
+
去过黑水山脉三次
```

此时“古修洞府线”不应继续无限靠运气。

---

# 10. 重复衰减

同一事件不应在短期内反复出现。

每个事件保存：

```text
lastTriggeredAt
runTriggerCount
lifetimeSeenCount
cooldown
repeatDecay
```

示意：

```text
第一次出现：100% 原权重
第二次出现：50%
第三次出现：20%
```

部分事件：

- `repeatable = false`
- 当前 Run 只能发生一次。

另一些日常事件允许重复，但正文/选项可根据 `repeatIndex` 有轻微变体。

---

# 11. 类别冷却

只对单个 Event 做冷却还不够。

需要 Event Category 冷却。

例如刚发生：

> 同门切磋

短时间降低：

```text
sparring
peer_conflict
combat_training
```

类事件权重。

避免玩家连续三次修炼都被同门拉去打架。

建议分类：

- cultivation
- npc_social
- combat
- exploration
- resource
- sect
- mystery
- danger
- opportunity
- world

一个事件可以拥有多个 tag。

---

# 12. 事件“记忆”与跨世重复

跨世后不能简单清空所有重复记录。

需要区分：

## Run Repeat

当前一世内的重复控制。

死亡回溯后清空大部分。

## Meta Familiarity

玩家在诸世中见过多少次。

不会完全清空。

Meta Familiarity 的作用不是降低所有事件概率，而是可以：

1. 简化已经非常熟悉的普通事件展示。
2. 解锁“熟练处理”选项。
3. 允许快速结算低价值重复事件。
4. 提高其变体事件权重。

例如玩家已经三世处理过：

> 灵药园虫害。

第四世可以出现：

```text
★【轻车熟路】按前世方法处理
```

直接结算，减少重复阅读。

同时可能解锁：

> 虫害背后其实来自一只特殊妖虫。

由普通事件进入隐藏 Chain。

# 13. 活跃主题 Run Themes

每次开始新推演时，从当前世界状态中选择 2～3 个“活跃主题”。

例如：

```text
THEME_OUTER_SECT_RIVALRY
THEME_ALCHEMY_ANOMALY
THEME_BLACKWATER
```

主题并不是固定主线，而是对相关事件增加权重。

同一个锚点：

第一世：

```text
外门竞争 + 丹阁异常
```

第二世：

```text
师徒关系 + 坊市散修
```

核心世界事件仍一致，但沿途经历不同。

## 13.1 主题来源

- 当前地点
- 境界阶段
- NPC关系
- 尚未解决的事件链
- 世界大事件
- 前世行为
- 少量种子随机

## 13.2 主题不能完全随机

必须保证与玩家当前阶段相关。

炼气三层不能抽到：

> 元婴宗门权力斗争。

---

# 14. 前世 Knowledge 如何影响事件池

Knowledge 有四种作用方式。

## 14.1 解锁选项

最经典：

```text
★【前世记忆】提前服下解毒丹
```

## 14.2 解锁新事件

例如知道：

> 丹阁陈执事每月初三会单独离宗。

下一世在初三可进入：

> 跟踪陈执事

事件池。

## 14.3 提高线索事件权重

玩家知道某处可能存在古修遗迹后，与遗迹相关的调查事件更容易进入候选池。

这不是“世界因为玩家知道而改变”，而是：

> 玩家知道应该注意什么、去哪调查。

## 14.4 排除无意义未知

已经明确知道某个普通谜题答案时，可以：

- 直接快速解决
- 或不再重复提供无价值的猜测型事件

# 15. 世界线偏移与事件池

改变重要事件后，系统计算 Worldline Divergence。

不同事件定义：

```text
worldlineImpact: 0 ~ 100
```

例如：

| 行为 | 影响示例 |
|---|---:|
| 改变普通任务结果 | 1 |
| 救下本应死亡的重要 NPC | 8 |
| 杀死重要 NPC | 12 |
| 提前揭露魔宗卧底 | 18 |
| 阻止宗门大战关键导火索 | 30 |

偏移不是单纯数值惩罚。

它主要影响：

1. 旧未来 Knowledge 的可信度。
2. 某些旧事件退出候选池。
3. 新事件进入候选池。
4. NPC 行动路线变化。
5. Run Themes 变化。

最终目标：

> 玩家越成功利用前世改命，就越快进入自己从未经历过的新未来。

---

# 16. 固定未来与随机未来的边界

为了让“知未来”成立，不能所有内容都随机。

建议世界事件分为三类。

## 固定锚定事件 Anchor Events

若关键原因未改变，通常会发生。

例如：

- 黑水秘境开启
- 某年宗门大比

它们构成世界的可学习性。

## 半固定事件 Elastic Events

大概率发生，但时间、参与者、结果可变。

例如：

- 赵长青试图夺取秘境宝物
- 某位弟子与玩家产生竞争

## 涌现事件 Emergent Events

根据当世状态动态进入池中。

例如：

- 某 NPC 因被救而引出的后续事件
- 某资源短缺形成的交易机会

三者共同形成：

```text
可预测的骨架
+
可变化的经历
```

---

# 17. 随机种子与“读档刷事件”

为了避免玩家通过刷新网页刷事件结果，Run 必须拥有服务端随机种子。

建议：

```text
runSeed
+
actionSequence
+
eventContext
→ deterministic random
```

同一个 Run、同一状态、相同行为顺序下，结果应基本可复现。

回到同一个 Anchor 开启新 Run 时，可以生成新的 Run Seed，用于产生不同日常经历。

但核心锚定事件不应因为 Seed 完全消失。

这样兼顾：

- 一世内部无法 F5 刷结果。
- 不同世可以产生不同经历。
- 关键未来仍然可以被学习。

---

# 18. 事件奖励原则

事件奖励优先级：

```text
信息 / 路线
>
关系 / 因果
>
资源选择
>
纯数值奖励
```

一个好事件最好让玩家得到：

> “我知道了新的事情 / 我打开了新的可能。”

而不是永远：

> “灵石 +20”。

---

# 19. 风险事件

随机事件不能只有奖励。

风险类型：

- 时间损失
- 灵石损失
- 受伤
- 中毒
- 关系恶化
- 宗门处罚
- 错过机会
- 引入仇敌
- 死亡

重要原则：

> 高风险事件必须尽量给玩家信息，让失败能够成为下一世的知识。

例如第一次因为不认识“噬灵藤”而重伤，结算后可以获得：

```text
KNOWLEDGE_DEVOURING_VINE
```

下一世出现：

> ★ 绕开藤蔓根系。

---

# 20. 事件可见性

玩家不需要知道所有概率。

UI 可以展示：

- “危险”
- “似乎有异”
- “你曾经历过”
- “前世记忆”
- “罕见机缘”

避免展示：

> 触发率 3.74%。

除非未来做专门的硬核模式。

---

# 21. V0.1 建议事件池规模

为了单人开发可控，第一版建议不是盲目追求事件数量，而是覆盖结构。

建议：

| 类型 | 数量 |
|---|---:|
| 日常随机事件 | 20～30 |
| 条件事件 | 15～20 |
| 小型事件链 | 5～8 条 |
| 核心事件链 | 1～2 条 |
| 稀有/奇遇事件 | 5～8 |
| 世界锚定事件 | 3～5 |

事件总节点大约 60～100 个即可形成第一版内容池。

其中很多节点可以复用规则模板，但文本、条件和结果不同。

---

# 22. V0.1 调度参数初始建议

以下只作为首轮试玩参数，不是最终平衡：

- 普通操作连续 2～4 次后，应大概率出现至少一次有意义反馈。
- 玩家连续 5 次主要行动都没有交互事件时，触发保护机制。
- 同一具体事件默认 3～8 个主要行动内不可再次出现。
- 同类事件刚触发后，类别权重降低。
- 每一世至少保证能接触 1 条主要事件链入口。
- 稀有事件不保证每世必出。
- 核心流程需要的关键事件不得依赖极低概率抽取。

最终以玩家体验调整，不以参数本身为目标。

---

# 23. 内容作者必须回答的字段

以后新增任何随机事件时，至少回答：

1. 为什么它在这里会发生？
2. 什么状态下可以发生？
3. 玩家为什么要做选择？
4. 最坏结果是什么？
5. 有没有信息价值？
6. 是否能引出后续事件？
7. 重复出现是否仍有意义？
8. 前世知道后能否产生变化？
9. 世界线改变后它是否仍成立？
10. 它属于哪个地点/主题/类别？

如果这些问题大部分没有答案，这个事件通常只是填充文本，不值得进入核心内容池。

---

# 24. 第一版验收场景

至少验证以下 5 种体验。

## 场景 A：同一阶段不同经历

两个新 Run 从同一 Anchor 开始，日常事件不同，但都能自然推进。

## 场景 B：不会连续重复

连续修炼不会多次出现完全相同的同门/灵气事件。

## 场景 C：奇遇改变路线

玩家遭遇一次稀有事件后，本世可进入一条此前不存在的路线。

## 场景 D：知识改变事件池

上一世获得一个人物秘密后，下一世能够主动接触新的调查事件。

## 场景 E：改命导致未知未来

玩家改变重要事件后，部分旧事件不再发生，同时出现新的后续事件。

# 25. 最终设计结论

《诸世问道》的长期内容核心不是：

```text
升级越来越慢
```

而是：

```text
同一个世界
+
不同的随机经历
+
不同的人物关系
+
不同的事件链
+
不同的前世知识
+
逐渐偏离的世界线
```

形成：

> **每一世都有熟悉的世界骨架，但总有一些事情与你记忆中的未来不同。**
