# 诸世问道：Knowledge 系统已确认决策

> 状态：Matt `grill-with-docs` 进行中的阶段性决策记录。
>
> 用途：记录第 10 轮已确认的 Knowledge 核心设计；完整 Grill 结束后再归并到正式设计文档。

## 1. Knowledge 的定义

Knowledge 不是人生流水日志，而是：

> **能够影响未来决策的可行动认知。**

典型范围包括：

- 人物秘密与动机。
- 事件发生时间与条件。
- 危险机制。
- 资源位置与出现窗口。
- 功法隐患。
- 敌人规律与弱点。
- 突破经验。
- 势力关系与政治信息。
- 隐藏地点、入口和路线。
- 曾经出现过的未来结果。

普通买卖、无决策价值的日常流水等进入一世记录，不进入核心 Knowledge。

## 2. Knowledge 记录来源

同一条信息必须保留来源语境，例如：

- 亲眼看见。
- 亲身经历。
- NPC 告知。
- 偷听。
- 文献 / 秘籍。
- 传闻。
- 多条线索推断。

来源影响可信度和可用方式。

Knowledge 至少应能够表达：

- 内容。
- 来源。
- 获得时间。
- 关联人物 / 地点 / 事件。
- 适用时间窗口。
- 当前可信 / 适用状态。

## 3. Knowledge 不等于世界绝对真相

Knowledge 代表玩家跨世保留的认知，不保证内容一定正确。

允许存在认知层级：

```text
传闻
↓
推断
↓
已验证事实
```

NPC 可以故意提供假情报，玩家也可能依据有限线索得出错误结论。

后续调查、亲历或新的 Knowledge 可以修正认知，但不能简单抹掉玩家曾经相信过什么。

## 4. 世界线变化后的适用性

旧 Knowledge 不因为现实未来被改变就删除。

典型适用状态包括：

- 仍可信。
- 可能变化。
- 已改变。
- 已失效。
- 存在矛盾。

例如前世记录“赵长青九月十五进入黑水并死于杀阵”，而本世玩家提前阻止他进入黑水时，该 Knowledge 应标记为已经被当前世界线改变，而不是消失。

核心体验是让玩家明确看到：

> **未来曾经如此，而这一次是我改变了它。**

## 5. 主动验证

Knowledge 可以产生主动调查玩法。

玩家可以围绕已有认知进行验证，例如：

- 提前蹲守一个时间窗口。
- 观察某 NPC 行踪。
- 查验物品成分。
- 找阵师判断某个危险。
- 查阅古籍。
- 用傀儡 / 法器进行试探。

验证需要承担时间、资源、关系或危险成本。

验证失败可能意味着：

- 原 Knowledge 错误。
- 当前世界线已变化。
- 玩家验证方法不足。
- 存在更深层原因。

## 6. Knowledge 链与推论

多条彼此相关的 Knowledge 可以形成知识链和推论。

例如：

```text
陈执事长期购买腐脉草
+
黑水灵酒中出现腐脉草
+
赵长青的酒来自丹阁
+
黑水秘境前经常有外门弟子失踪
↓
推论：丹阁可能在利用外门弟子测试某种东西
```

系统不应自动把全部世界真相直接公布给玩家。

形成推论后，更适合：

- 提示“这些事情可能存在联系”。
- 开放新的调查方向。
- 开放新的对话 / 事件选项。

## 7. Knowledge 的收益方式

Knowledge 主要改变信息和规则，不直接堆叠数值属性。

典型收益：

- 揭示敌人空门。
- 缩短已知路线时间。
- 提前规避有毒丹药。
- 使用 NPC 秘密作为谈判筹码。
- 提前截胡机缘。
- 修正错误突破步骤。
- 发现正确老师、资源或盟友。

原则上不采用“每条 Knowledge +1% 全属性”等收集式数值奖励。

## 8. 使用未来信息的社会风险

Knowledge 不是无成本对话作弊器。

如果玩家在没有身份、证据和合理信息来源的情况下表现出对某 NPC 未来和秘密的异常了解，NPC 可以产生：

- 怀疑。
- 警惕。
- 敌意。
- 试探。

玩家可能需要先构造合理信息来源、制造证据或引导 NPC 自己得出结论。

这使 Knowledge 与人物关系、身份、调查和势力政治直接联动。

## 9. 死亡只产生角色合理能知道的信息

死亡不自动解锁完整攻略。

如果玩家只知道“进入石门后三息内被未知力量瞬杀”，获得的 Knowledge 也只能停留在这一层。

下一世可以通过观察、查古籍、找阵师、使用傀儡或再次试探逐步把认知深化为：

```text
未知致命攻击
→ 阵法攻击
→ 某类阵法
→ 具体触发条件
→ 阵眼 / 破解方式
```

核心原则：

> **死亡提供线索，不保证提供答案。**

## 10. 命书式 UI

Knowledge UI 不使用传统“主线 / 支线 / 已完成任务”结构。

采用命书 / 前世档案式知识网络，主要按以下实体组织：

- 人物。
- 地点。
- 事件。
- 功法。
- 势力。
- 资源。
- 危险。
- 机缘。

每个实体节点可以显示已知事实、来源、可信状态和关联对象。

同时提供“当前可利用的前世机会”摘要，例如：

- 距某关键人物出现还有多少天。
- 某机缘可能在何时出现。
- 当前已知的未来危险。
- 已验证但尚未利用的资源窗口。

## 11. 信息收敛

Knowledge 必须从一开始防止无限日志化。

机制包括：

- 重复信息自动归并。
- 多次观察提炼为稳定规律。
- 过时信息降低展示优先级。
- 矛盾信息聚合到同一知识主题。
- 细节自动形成摘要。
- 玩家可以关注、收藏和标记重点。

例如多次记录赵长青在初三上午出现在丹阁，不应永远保留成数十条时间日志，而应归并为：

> 赵长青通常在初三上午前往丹阁。

核心原则：

> **Knowledge 是结构化认知网络，不是无限增长的事件日志。**
