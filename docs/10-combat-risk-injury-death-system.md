# 诸世问道：战斗、风险、伤势与死亡系统

> 状态：设计基线 V0.1  
> 目标：让随机事件、秘境、历练和突破真正具有风险，使“死亡—结算—回溯”成为可规划的核心玩法，而不是无意义惩罚。

---

# 1. 设计原则

本游戏不是以高频战斗为核心的数值 RPG。

战斗系统的主要职责是：

- 给事件选择提供真实代价
- 让“是否冒险”成为决策
- 让装备、术法、伤势和准备产生价值
- 产生死亡、逃脱、重伤、夺宝等不同结果
- 为前世 Knowledge 提供实际用途

因此战斗必须满足：

> **少而有意义、风险可解释、结果不只胜负、死亡可以学习。**

禁止把游戏做成：

```text
遇怪
→ 自动战斗
→ +经验
→ 下一只怪
```

---

# 2. 风险层级

所有危险事件先给出风险等级，而不是直接进入战斗。

建议：

| 风险 | 含义 |
|---|---|
| 安全 | 几乎无死亡风险 |
| 低 | 可能轻伤/资源损失 |
| 中 | 可能重伤，准备不足会死亡 |
| 高 | 明显死亡风险，需要准备 |
| 极高 | 当前实力通常不应挑战 |
| 未知 | 玩家缺乏足够情报 |

风险展示必须来自玩家可知信息。

例如第一次遇到洞府阵法：

> 风险：未知

前世死过一次后：

> ★ 前世记忆：此阵会在第三息爆发雷火，风险极高。

知识直接改变玩家对风险的认知。

---

# 3. 风险来源

风险不限于战斗。

## 3.1 战斗风险

- 妖兽
- 修士
- 宗门冲突
- 劫修
- 秘境守卫

## 3.2 环境风险

- 毒瘴
- 极寒/烈焰
- 灵气暴动
- 陷阱
- 崩塌
- 禁制

## 3.3 修炼风险

- 强行突破
- 走火入魔
- 经脉逆行
- 丹毒
- 功法冲突

## 3.4 社会风险

- 得罪核心 NPC
- 宗门处罚
- 暴露秘密
- 欠下恶性因果
- 被追杀

## 3.5 时间风险

某些选择不伤血，但会浪费数月甚至数年。

在修仙游戏里：

> **失去时间本身就是风险。**

---

# 4. 战斗属性

V0.1 保持轻量。

核心战斗状态：

```text
生命 Life
灵力 Spirit
攻击 Offense
防御 Defense
速度 Speed
神识 Perception
```

实际值由以下来源推导：

```text
境界
+ 体魄
+ 功法
+ 术法
+ 法器
+ 符箓
+ 当前伤势
+ 临时状态
```

不建立复杂的几十项战斗属性。

---

# 5. 战力差距

境界差距必须有明显意义。

例如炼气三层面对筑基修士时，不能因为一次高随机骰子直接正面击杀。

建议区分：

```text
同阶：正常判定
小幅越阶：高风险但可能
明显越阶：只有特殊条件才可能
大境界压制：正面对抗几乎不可行
```

但事件可以提供非正面对抗路线：

- 下毒
- 阵法
- 埋伏
- 逃跑
- 借助 NPC
- 使用前世情报
- 引妖兽相争

这样“知识”可以弥补部分战力差距，但不能取消境界体系。

---

# 6. 战斗不是传统回合制页面

首版推荐采用 **战斗阶段 + 决策节点**。

例如：

```text
遭遇赵长青
↓
系统评估初始态势
↓
第一决策
  ├ 正面出手
  ├ 使用符箓
  ├ 拖延时间
  └ 尝试逃跑
↓
规则结算
↓
态势改变
↓
第二决策（如有必要）
↓
结果
```

一个普通战斗通常 1～3 次关键选择即可结束。

不要设计成每场战斗点击 20 次“普通攻击”。

---

# 7. 战斗判定

战斗结果采用规则计算 + 可控随机。

概念公式：

```text
EffectivePower =
基础战力
× 状态修正
× 克制修正
× 准备修正
× 场景修正
```

然后结合双方差距决定结果区间。

随机只负责：

- 同一合理结果区间内的波动
- 是否产生额外伤势
- 是否触发稀有战斗事件

随机不得把“必败局”变成无条件大胜。

---

# 8. 战斗结果不是只有胜负

至少支持：

1. 完胜
2. 胜利但受伤
3. 惨胜
4. 僵持后脱离
5. 成功逃跑
6. 逃跑失败
7. 战败被俘/被抢
8. 重伤存活
9. 死亡
10. 内容定义的特殊结果

这非常重要。

失败不应自动等于死亡。

---

# 9. 逃跑机制

逃跑必须是正式玩法。

影响因素：

- 速度
- 身法
- 地形
- 敌人速度
- 是否被包围
- 事前准备
- 符箓/法器
- 前世情报

例如：

```text
第一次：
进入洞府后才发现赵长青翻脸
→ 退路被封
→ 逃跑失败

第二世：
★ 提前记住侧门位置
→ 逃跑难度明显下降
```

这让 Knowledge 不一定带来“打赢”，也可能带来“活下来”。

# 10. 伤势系统

伤势采用层级 + 标签。

## 10.1 基础层级

```text
健康
轻伤
中伤
重伤
濒死
```

## 10.2 特殊伤势标签

例如：

- 经脉受损
- 丹田受创
- 神识震荡
- 中毒
- 火毒
- 寒毒
- 暗伤
- 根基受损

特殊伤势可影响：

- 修炼效率
- 突破
- 战斗
- 移动
- 事件池
- NPC 行为

---

# 11. 伤势要产生新的事件

伤势不是单纯负面 Buff。

例如重伤后，事件池可以新增：

- 师姐探望
- 丹阁求药
- 黑市购买禁药
- 神秘修士提出治疗条件
- 敌对 NPC 趁虚而入

因此：

> **坏状态也应该产生内容。**

---

# 12. 治疗

治疗方式包括：

- 自然恢复
- 丹药
- 宗门医治
- NPC 帮助
- 特殊功法
- 秘境机缘

不同方式消耗：

```text
时间 / 灵石 / 宗门贡献 / 因果 / 人情
```

例如免费找师父疗伤，可能产生：

> 授业之恩 / 欠下人情。

使治疗和 NPC/因果系统连接。

---

# 13. 中毒系统

V0.1 中毒需要支持：

- 毒素类型
- 发作时间
- 强度
- 是否已知
- 是否有解法
- 持续效果

典型黑水事件：

```text
赵长青下毒
↓
玩家第一次不知道
↓
数个事件后毒发
↓
死亡
↓
获得 KNOWLEDGE_ZHAO_POISON
```

第二世：

- 提前购买解毒丹
- 拒绝饮用
- 假装中毒
- 反向利用

形成跨世玩法。

---

# 14. 死亡原因

死亡必须记录明确原因。

例如：

```text
DEATH_COMBAT
DEATH_POISON
DEATH_BREAKTHROUGH
DEATH_TRAP
DEATH_OLD_AGE
DEATH_QI_DEVIATION
DEATH_EVENT_SPECIAL
```

并保存：

- 直接原因
- 关键前置事件
- 可学习信息
- 是否首次死亡于此原因

---

# 15. 死亡必须可学习

死亡结算至少回答：

1. 我为什么死？
2. 我本来能否避免？
3. 我学到了什么？
4. 下一世能出现什么不同？

好的死亡：

```text
你不知道赵长青会下毒
↓
死亡
↓
获得明确知识
↓
下一世出现新方案
```

坏的死亡：

```text
随机暴击
↓
死亡
↓
什么也没学到
```

后者应尽量避免。

---

# 16. 死亡价值等级

可将死亡按信息价值划分：

### 普通死亡

主要结束当前 Run。

### 学习型死亡

获得明确 Knowledge / Insight。

### 关键死亡

解锁重大事件链或世界秘密。

### 特殊死亡

触发罕见诸世事件，例如心魔、天衍异常、隐藏剧情。

不是死亡越多越好，而是：

> **不同死亡应该推动玩家理解世界。**

---

# 17. 防止“主动送死刷知识”

必须限制。

规则：

1. 相同死亡原因重复收益快速衰减。
2. 已获得完整 Knowledge 后重复死亡不再奖励。
3. Insight 只在第一次或更深入阶段显著增长。
4. 明知必死但未产生新变量时，不额外奖励。

玩家应尝试新的路线，而不是反复撞同一面墙。

---

# 18. 非死亡失败

为了避免每一世都靠死亡结束，支持“路线走废”。

例如：

- 根基严重受损
- 错过关键秘境
- 被逐出宗门
- 核心 NPC 死亡
- 筑基资源彻底断绝

玩家可以选择：

1. 继续这一世，寻找新路线。
2. 把剩余时间用于探索 Knowledge。
3. 主动结束推演。

这样人生更丰富。

---

# 19. 风险提示原则

游戏不能隐藏所有风险，否则选择等于猜答案。

信息分三层：

### 已知

玩家有充分信息，明确提示风险。

### 模糊

只知道有危险，不知道具体原因。

### 未知

第一次接触，无法判断。

前世知识可以把：

```text
未知 → 模糊 → 已知
```

这就是知识成长的一部分。

---

# 20. 风险与奖励

高风险不一定给更高纯数值奖励。

高风险可以换来：

- 更深情报
- 新事件链
- 稀有人物关系
- 隐藏地点
- 特殊功法
- 更高层级的未来

避免简单的：

> 风险越高 = 灵石越多。

---

# 21. 战斗事件池

战斗结束后，根据结果进入不同事件池。

例如：

```text
完胜
→ 追击 / 搜索 / 审问

惨胜
→ 疗伤 / 求援 / 被人发现

逃跑
→ 追杀 / 躲藏 / 求助

被俘
→ 谈判 / 越狱 / 因果交换
```

使战斗成为事件网络的一部分，而非独立小游戏。

---

# 22. 前世知识如何改变战斗

Knowledge 可以：

- 暴露敌人真实实力
- 暴露敌人术法
- 暴露陷阱
- 解锁提前准备
- 解锁特殊撤退路线
- 解锁借力打力方案
- 解锁对话/威胁方案

不建议直接：

> 前世知识 = 战斗力 +50%。

核心应该是**新决策**。

---

# 23. V0.1 战斗范围

首个可玩原型只需实现：

- 1 套轻量战斗判定
- 3 类敌人
- 逃跑
- 轻/重伤
- 中毒
- 死亡
- 前世知识改变危险事件

建议敌人：

1. 普通低阶妖兽
2. 同阶修士
3. 赵长青核心事件战

不做：

- 复杂技能树
- 元素反应大系统
- 装备强化
- 连击系统
- PvP

---

# 24. 关键验收场景

## 场景 A：风险可理解

玩家看到不同危险程度时，能判断是否值得继续。

## 场景 B：逃跑有价值

无法战胜的敌人可以通过准备和情报逃脱。

## 场景 C：死亡带来知识

第一次因赵长青毒杀死亡后，第二世必须出现至少一个可改变结果的方案。

## 场景 D：坏状态产生内容

重伤后至少存在新的治疗/NPC事件，而不是只能等时间恢复。

## 场景 E：不能 F5 刷胜负

同一 Run 同一条件下刷新页面不得重新随机获得不同战斗结果。

---

# 25. 规则不变量

1. AI 不决定战斗胜负。
2. 战斗结果由规则和 RunSeed 共同确定。
3. 关键死亡必须记录原因。
4. 同一死亡 Knowledge 不能无限重复获取。
5. 大境界压制不能被普通随机完全逆转。
6. 伤势必须影响后续游戏状态。
7. 失败允许存在非死亡结果。
8. Knowledge 主要改变选择和准备，不直接无限增加战斗属性。

---

# 26. 当前结论

战斗系统在《诸世问道》中不是主循环，而是：

> **把玩家的修炼、资源、前世知识和风险判断转化成真实后果的执行器。**

理想体验不是“我刷了多少怪”，而是：

> 第一次我不知道洞府里的人会杀我；第二次我知道，却依然打不过；第三次我提前准备退路、解毒丹和帮手，终于让这一段命运走向完全不同的结局。
