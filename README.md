# 诸世问道（暂定名）

一款面向 **Steam / Windows** 的 **东方修仙像素人生模拟 Roguelite RPG**。

> 活一世，死一次，带着记忆与选择重新走人生。

## 项目定位

玩家直接控制一名修士在可探索的像素修仙世界中移动、修炼、历练、接触人物、探索秘境与战斗。死亡不是普通失败界面，而是核心玩法入口：系统会总结这一世，玩家选择下一世的天衍锚点，并在“承世”与“悟世”之间做一次取舍。

游戏真正的长期深度来自：

```text
可探索像素世界
+
条件 / 随机 / 连锁事件
+
NPC 与世界状态
+
Knowledge
+
Anchor
+
承世 / 悟世
+
多世回溯
```

项目不做完整世界模拟，也不以复刻《Project Zomboid》的系统规模或《八方旅人》的 HD-2D 制作规格为目标。

核心原则：

> **地图负责沉浸与空间选择，事件系统负责内容深度，多世回溯负责独特玩法。**

AI 只用于人生评价润色、内容生产辅助、测试和开发自动化等非权威能力；游戏规则和世界事实由代码与内容配置决定。

## 核心循环

```text
新世界
  ↓
初始天衍锚点
  ↓
开始一世
  ↓
在地图中移动 / 修炼 / 社交 / 探索 / 战斗 / 秘境
  ↓
条件事件 + 随机事件 + 连锁事件
  ↓
成长 / Knowledge / 功法 / 法宝 / 资源
  ↓
死亡（也允许主动坐化）
  ↓
一世评价
  ↓
选择下一世 Anchor
  ↓
承世一项成果  OR  悟世一个词条
  ↓
回溯次数 -1
  ↓
下一世
  ↓
利用前世 Knowledge 改变未来
```

## 当前核心规则

### 有限回溯

- 每个新世界基础拥有 **10 次回溯**。
- 只有死亡后真正开启下一世时才消耗 1 次。
- 玩家可主动坐化，规则上仍然属于死亡。
- 回溯耗尽后的继续方式重新按 Steam 单机体验设计；旧“账号级付费回溯额度”不再是当前基线。

### 多天衍锚点

- 新世界创建时自动建立初始大境界 Anchor。
- 之后 **每个大境界最多建立一个 Anchor**。
- 除初始 Anchor 外，由玩家在该大境界内自行选择时机手动“定世”。
- Anchor 建立后不可覆盖、不可更新。
- 死亡后可以从所有已建立 Anchor 中任选一个作为下一世起点。

### Knowledge

Knowledge 是玩家在当前世界中真实获得的未来情报、人物秘密、地点信息、危险线索等。

- 跨 Anchor 永久保留。
- 记忆不会因世界线变化删除，但可以变成“可能变化 / 已失效 / 矛盾”。
- 真正创建新世界时清空。

### 承世 / 悟世

死亡结算时二选一。

**承世**：从死亡时仍合法拥有或掌握的成果中带走一项进入紧接着的下一世。

- 可承世：功法、法宝、装备、丹药、普通物品等允许成果。
- 不可承世：境界、修为。
- 高境界成果可以带回低境界 Anchor，但仍受自身使用条件限制。
- 承世不是永久 Meta 背包。

**悟世**：放弃实体承世，根据这一世真实经历生成最多 3 个词条候选并选择一个。

- 词条不是抽卡。
- 空白人生可以没有任何候选。
- 已有同源词条可通过新的悟世升级。
- 词条库跨 Anchor 保留；每世最多同时装备 **5 个词条**。

### 修炼与节奏

- 修炼消耗游戏内时间，不是现实挂机时间。
- 修为达到要求只是获得突破资格。
- 玩法节奏由有效行动、瓶颈、事件密度、地图探索和重大选择共同控制。
- Event Pressure 不允许靠重复点击或无意义移动刷取重大事件。

### 世界与随机

正式版采用预设内容模块组合，而不是运行时随机生成整个世界。

同一 Anchor 下：

- 关键人物身份、重大事件根因、重要传承等“锚点命运”相对稳定。
- 日常遭遇、普通奇遇、市场供给、部分支线等“一世变数”可以变化。
- 重大结果使用与事件上下文绑定的确定性随机，不允许通过无关操作“烧随机数”。

## 当前表现方向

不是纯文字菜单，也不是全模拟沙盒。

```text
像素地图探索
  ↓
进入地点 / 接触 NPC / 调查 / 战斗
  ↓
Event Engine 根据当前状态生成可用事件与选择
  ↓
Knowledge / 词条 / 功法 / 物品改变选项
  ↓
世界状态继续演化
```

V0.1 视觉目标：

- 俯视 / 斜俯视像素地图。
- 2D 像素角色。
- 东方修仙场景。
- 少量灯光、雾效、粒子强化氛围。
- 关键事件、NPC、死亡与轮回允许使用立绘 / 插画。
- Anchor / Knowledge / 承世 / 悟世继续使用墨青、暗金、青玉、命书 / 道纹等既有视觉语言。

## V0.1 目标

V0.1 仍只验证“黑水三世”核心闭环，但改为真实桌面像素 RPG 纵切：

```text
青玄宗
↓
角色实际移动 / 修炼 / 接触 NPC
↓
青石坊市
↓
准备资源
↓
黑水山脉
↓
事件 / 战斗 / 探索
↓
第一世死亡
↓
Knowledge
↓
第二世改变路线
↓
新的死亡与 Knowledge
↓
第三世 Knowledge + 词条进入新内容
↓
承世
```

V0.1 内容上限建议：

- 1 个宗门区域。
- 1 个坊市。
- 1～2 张黑水山脉地图。
- 1 个黑水秘境。
- 5～8 个重要 NPC。
- 5 种以内敌人。
- 3～5 门功法。
- 10 个以内战斗技能。

V0.1 不以完整境界、开放世界、宗门经营、大规模制造、复杂经济模拟或大量战斗内容为验收条件。

## 技术方向

当前已经锁定：

```text
平台：Steam / Windows 优先
形态：单机桌面像素 RPG
架构：本地权威游戏运行时
内容：Event Engine + 数据驱动
测试：必须支持 AI CLI 自动开发与 Scenario / Headless 测试
```

当前只保留两个引擎候选：

```text
A. Java + libGDX
B. Godot + C#
```

最终选择将依据像素地图制作效率、AI/Codex 自动化、Headless E2E、长期维护和 Steam 打包成本确定。

旧技术方向已经废弃：

- uni-app x / H5（Web）/ 微信小程序首发路线。
- Spring Boot + REST 作为单机游戏玩法运行时。
- PostgreSQL + MyBatis-Flex 作为首版本地存档。
- LiteFlow 作为首版游戏流程编排。

详细技术方向见 [`docs/06-desktop-game-technical-baseline.md`](./docs/06-desktop-game-technical-baseline.md)。
