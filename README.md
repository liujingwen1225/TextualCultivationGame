# 诸世问道（暂定名）

一款以 **未来推演、死亡回溯、前世情报、长期修仙成长** 为核心的东方文字修仙 Roguelite / RPG。

> 经历未来，记住死亡，然后重新选择。

## 项目定位

玩家扮演一名普通修士，而不是天道或世界管理者。玩家通过修炼、历练、秘境、人物关系与事件选择推进一世人生；当本次推演死亡或失败后，回到天衍锚点，物质成果消失，但可保留部分情报、认知与悟道，再利用前世经验改变新的时间线。

项目首先是一款 **长期游玩的修仙游戏**。AI 是辅助能力，不是核心规则引擎：

- 游戏代码决定数值、条件、结果和状态变化。
- 内容配置决定事件结构、选择和因果链。
- AI 可用于事件润色、NPC 表现、人生总结和内容生产辅助。
- 核心游戏不依赖自由输入，也不依赖运行时 AI 才能成立。

## 核心循环

```text
建立天衍锚点
    ↓
开始一世推演
    ↓
修炼 / 历练 / 交友 / 探索 / 决策
    ↓
时间与寿元推进
    ↓
获得资源 / 功法 / 情报 / 因果
    ↓
突破 / 失败 / 死亡
    ↓
诸世结算
    ↓
保留部分情报与悟道
    ↓
回到锚点
    ↓
解锁前世记忆选项
    ↓
改变未来，产生世界线偏移
```

## 长期成长原则

境界提升不能过快，也不能靠单纯拉长经验条制造时长。

正式游戏的成长由以下内容共同构成：

```text
修为
+
功法理解
+
瓶颈
+
资源
+
修炼环境
+
NPC关系
+
宗门身份
+
事件与秘境
+
前世 Knowledge / Insight
```

首轮无攻略玩家第一次成功筑基，目标是需要多轮推演与约 **15～30 小时有效游玩**；筑基以上继续按长期内容扩展。

跨世之后，玩家可以因为掌握路线、人物、机缘和瓶颈处理方法而明显缩短重复阶段，但不能直接继承修为和境界。

核心体验是：

> 这一世花十年踩坑，下一世用三年解决，再把省下来的七年投入从未见过的未来。

## 原型与正式平衡分离

项目从一开始区分：

- `DEVELOPMENT`：开发/自动测试使用的高速平衡配置。
- `STANDARD`：正式长期游戏配置。

V0.1 的 15～30 分钟目标只用于让测试玩家体验一次完整的：

```text
未知 → 失败/死亡 → 获得前世知识 → 回溯 → 改变结果
```

**V0.1 不要求 30 分钟筑基。**

## 当前明确边界

V0.1 采用固定行动与事件选项，不做自由输入。第一阶段只验证：

1. 时间与寿元是否形成有效压力。
2. 缓慢修炼是否仍然有持续反馈和决策。
3. 瓶颈是否迫使玩家进入世界，而不是无限闭关。
4. 事件选择是否能形成因果。
5. 死亡回溯是否带来“再来一世”的动力。
6. 前世情报是否能真正解锁新决策，而非仅提供攻略文本。
7. 相同阶段是否因为前世 Insight 而减少重复劳动。
8. 改变未来后，旧情报是否会逐渐失效并形成新的未知。

## 开发原则

- **游戏先于 AI**：没有模型 API，核心游戏仍可完整运行。
- **长期成长但不做无意义 grind**：升级慢靠瓶颈、选择、资源、事件和时间压力，而不是巨型经验条。
- **系统先于内容量**：先验证循环，再扩充宗门、秘境、功法和剧情。
- **规则先于文案**：事件结果必须由规则和配置决定，AI 只负责表现。
- **知识也是资源**：跨世继承的核心不是装备，而是玩家对世界的认知。
- **一个人可维护**：优先数据驱动和内容工具，避免大地图、全 NPC Agent、复杂开放世界模拟。

## 第一阶段目标

做出一个短时间即可体验核心特色、但使用长期成长规则的可玩原型：

> 第一世因未知而死亡 → 结算获得前世情报 → 回到锚点 → 同一事件出现新的“前世记忆”选项 → 改写事件结果 → 进入此前未见的未来。

原型验证成功后，再逐步扩充炼气完整阶段、筑基长期目标、更多人物关系、秘境和事件网络。
